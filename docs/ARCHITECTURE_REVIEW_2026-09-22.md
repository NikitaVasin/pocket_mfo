## Подтверждённые находки

### 1. Обход лимита скалярного поля — P2, исправлено

До исправления `scalar` ограничивал строки 4096 байтами, но возвращал
`json.Number.String()` без проверки длины. Авторизованный постбек с `offer_id`
в виде числа из 4097 цифр принимался с HTTP 200, записывал дополнительный
параметр и отправлял событие; такая же строка получала HTTP 400.

Влияние: нарушение ограничения входных данных, увеличение записи и события.
Для воспроизведения нужны секрет провайдера и действительный токен ссылки;
общий лимит тела 256 KiB продолжал действовать. Это не обход авторизации
и не доказательство неограниченного расхода памяти.

Исправление: единый лимит после преобразования скаляра
([conversion.go:113](../plugins/partnerlinks/conversion.go#L113)).
[HTTP-регрессия](../plugins/partnerlinks/postback_test.go#L11) до исправления
падала: `status = 200, want 400`. После исправления проверяет отказ для строк
и чисел длиной 4097, отсутствие изменений записи и сетевых событий, а также
успех на границе 4096.

### 2. Нетипизированная конверсия между HTTP, БД и аналитикой — исправлено

Ранее `api.go` совмещал разбор запросов, бизнес-валидацию и сетевую доставку.
Конверсия передавалась как `map[string]any`; revenue использовал прямые
type assertions, а `collect` получал статус отдельно от той же конверсии.
Это хрупкая внутренняя связь, а не подтверждённая внешняя panic-уязвимость:
существующий обработчик проверял revenue перед отправкой.

Теперь внутри того же пакета:

| Файл | Ответственность |
| --- | --- |
| `api.go` | Выдача ссылки, редирект, общий ограниченный JSON decoder |
| [postback.go:67](../plugins/partnerlinks/postback.go#L67) | HTTP-аутентификация и последовательность проверка → сохранение → доставка |
| [conversion.go:14](../plugins/partnerlinks/conversion.go#L14) | Закрытый тип `conversionData`, чистый разбор и валидация |
| [conversations.go:199](../plugins/partnerlinks/conversations.go#L199) | Транзакционные изменения одной конверсии |
| [appmetrica.go:16](../plugins/partnerlinks/appmetrica.go#L16) | AppMetrica transport, таймауты и обработка ответов |

Произвольная карта остаётся только для внешнего постбека и JSON-конверта.
Новые пакеты, интерфейсы, публичные типы и runtime-зависимости не добавлены.

Сохранены важные различия: отсутствующие поля не стирают данные в БД,
но не попадают в событие текущего постбека; непустой `extra` заменяется целиком;
строка суммы `"0"` сохраняется; click не содержит `conversion: null`;
токен принимается только как строка. Новая
[проверка контракта](../plugins/partnerlinks/postback_test.go#L51) покрывает
сохранение необязательных значений и состав исходящего события.

## Архитектурные границы, которые сохранены

- **Schema Lock:** точные сочетания HTTP-метода и разрешённого маршрута;
  защита служебных записей действует и для суперпользователей и batch.
  Внутренние context keys остаются закрытыми для внешнего кода.
- **Polymorphic Relation:** JSON и служебные relations меняются в одной
  транзакции; раскрытие связей делегирует проверку ViewRule PocketBase.
- **Variants:** дерево условий ограничено по глубине/числу узлов,
  SQL строится из проверенной схемы и экранированных значений;
  `nil` и пустое API rule не объединяются. Публикация атомарна.
- **Singleton:** уникальность обеспечивает индекс SQLite, а не предварительный
  подсчёт. Интеграция с Variants остаётся в общей транзакции.
- **Dynamic Link:** поле валидирует контракт и HTTP(S) URL, само не делает
  сетевых запросов. Политики используют существующие Variants/Singleton.
- **Partner Links:** снимок экспериментов, уникальность заявки, TTL и владение
  остаются в серверной модели. AppMetrica использует фиксированные адреса,
  контекст запроса, таймаут 2 секунды и запрет редиректов. Ошибки транспорта
  не раскрывают URL с ключом. URL постбеков редактируется до activity logger.

Сохранение конверсии и доставка в AppMetrica не являются общей транзакцией:
при сетевой ошибке запись остаётся, ответ — 502. Повтор может отправить событие
заново. Это явно заданный контракт проекта; очередь, retry и дедупликация
не добавлялись. Их внедрение потребовало бы отдельного изменения поведения.
