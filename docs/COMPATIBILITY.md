# Совместимость каталога v1.0.0

Этот контракт относится к первому выпуску всего каталога: десяти Go-плагинам и шести Dart/Flutter-пакетам. Версия каталога хранится в [VERSION](../VERSION), Git-тег — `v1.0.0`. Версии PocketBase, SDK, схемы Typed Config и приложения-потребителя — отдельные величины.

## Версии и платформы

| Компонент | Критерий интеграции v1.0.0 |
| --- | --- |
| PocketBase | Поддерживаемая и проверенная версия **v0.40.4**. Иная версия, включая patch, требует отдельного прогона: плагины используют серверные hooks и экспериментальный UI API |
| Go | Минимум **1.27** по go.mod; проверено на **1.27.0**. Более новый toolchain сам по себе не подтверждает совместимость; повторите сборку, race/vet и интеграционные проверки |
| Flutter / Dart | Проверенная связка **Flutter 3.47.5 / Dart 3.13.4**, закреплена FVM. Для всех шести пакетов вместе требуется Dart **>=3.13.4 <4.0.0**; меньший минимум отдельного пакета не является минимумом фасада |
| Dart-зависимости | В каталоге — корневой workspace и единый pubspec.lock. В потребителе — разрешённый pub get граф и его собственный lockfile; совпадение диапазонов pubspec без анализа/тестов недостаточно |
| Android | Нативная интеграция Firebase/AppMetrica рассчитана на Android. Сам app_messaging_flutter задаёт minSdk 23, compileSdk 36 и Java 17; итоговые требования приложения — максимум требований Flutter и всех его плагинов. Проверена debug APK-сборка примера, не все устройства/API уровни |
| iOS | Сам app_messaging_flutter задаёт iOS 15.0; итоговый deployment target учитывает также Flutter/Firebase и остальные зависимости. Проверена сборка симулятора без подписи. Доставка APNs требует совместимой подписанной сборки и проверки устройства |
| Web | Проверены интерфейс примера, PocketBase и браузерное открытие ссылок. Мобильные AppMetrica Analytics/Push, регистрация push-устройства и нативный WebView не становятся web-функциями; пример использует PreviewAnalytics |
| Desktop | Отдельные нижние пакеты имеют fallback открытия ссылок, но полная связка гостевой сессии, аналитики и пушей на desktop в v1.0.0 не заявлена проверенной |
| Инструменты проверки | CI использует Node.js 24, Playwright из package-lock.json и Docker Compose v2. Они не являются зависимостями Go-бинарника production |

Минимумы нативного плагина не заменяют сборку целевого приложения. Не понижайте SDK или транзитивные зависимости через overrides ради прохождения pub get. Если существующий проект использует другую связку, сначала зафиксируйте расхождения и проверьте её отдельно, не обновляя проект без согласованного объёма.

## Обязательные условия архитектуры и данных

| Область | Что агент обязан проверить до подключения |
| --- | --- |
| Единая версия каталога | Все Go-импорты относятся к одному module path `github.com/NikitaVasin/pocket_mfo`; для v1 суффикс `/v1` не добавляется. Flutter-пакеты берутся из одного полного checkout на том же выпуске, сохраняются соседние path-зависимости |
| Жизненный цикл | Один core.App; Register до Bootstrap/Start; Schema Lock последним. Собственные миграции запускаются до начала работы auth-зависимых endpoints. Demo-миграции в production не подключаются |
| Существующая БД | Нет конфликтов с именами/типами служебных коллекций, полей и индексов. Миграции проверены на новой БД и копии существующей, повторный запуск сохраняет данные; есть проверенный путь восстановления бэкапа |
| Правила доступа | Сохранено различие nil и пустого правила PocketBase. Проверены неавторизованный, разрешённый пользователь, другой владелец/auth-коллекция и superuser. Variants, UI-скрытие и MCP allowlist не заменяют авторизацию |
| Зависимости плагинов | Для общей политики Dynamic Link нужны Variants + Singleton; Partner Links требует регистрации Dynamic Link, Push-атрибуция — callback push.Attribution. Остальные зависимости и порядок — в руководстве интеграции; регистрация одного плагина не означает включение всего каталога |
| Auth во Flutter | Один PocketBase/authStore и один владелец жизненного цикла SDK. Фасад создаёт гостей, не имеет guestEnabled:false и не объединяет гостя с аккаунтом. При несовместимой auth-модели используются нижние пакеты с явной реализацией жизненного цикла |
| Идентификация аналитики | SDK, Post API и Push настроены на одно согласованное приложение AppMetrica; profileId равен PocketBase user.id. При нескольких auth-коллекциях исключены совпадающие ID либо приложения аналитики разделены |
| Typed Config | Типы/Definitions/mapping согласованы со схемой источников и правами чтения. При удалении источника удаляется целый зависимый item. Клиентские DTO сгенерированы для используемой Schema.Version, все возвращаемые type поддержаны рендерером |
| Эволюция схемы | Schema.Version повышается вместе с изменением контракта; проверены данные и поддерживаемые версии клиентов. Старое приложение отвергает неизвестный тип блока: одного повышения версии недостаточно для обратной совместимости. Нужна совместимая миграция либо разделение выдачи по версиям приложения |
| Эксперименты и воронки | Отдельные измерения эксперимента явно компонуются приложением. Новые тесты independent, старые shared не переключаются автоматически. События показывают фактическую видимость, используют exposures показанных записей; resolve и поздний postback сохраняют тот же контекст |
| Постбеки | Метод/поля/статусы, 43-символьный токен, секрет, lead ID, timestamp и Revenue соответствуют контракту партнёра. Подтверждённая доставка дедуплицируется, unknown требует сверки; exactly-once и автоматические возвраты не предполагаются |
| Native-конфигурация | applicationId/bundle ID, Google-файлы, APNs/FCM sender и подпись относятся к целевому проекту. Автоконфигуратор рассчитан на стандартные Android app и iOS Runner без Android flavors; иная структура интегрируется отдельно |
| Развёртывание | Постоянная SQLite/файлы, HTTPS и доступность redirect/postback, исходящие API, секреты, cron и бэкапы настроены. Несколько реплик с общей SQLite и мультитенантная маршрутизация AppMetrica не объявляются поддерживаемыми без отдельной архитектуры |

## Как принять решение о совместимости

Перед изменениями агент добавляет в `docs/integration-plan.md` таблицу:

| Критерий | Требование каталога | Факт в приложении | Проверка | Решение |
| --- | --- | --- | --- | --- |
| Версии / auth / схема / платформы / внешние службы | Конкретное требование выше | Найденное значение или неизвестно | Команда, тест, миграция, устройство | Соответствует / нужна адаптация / не проверено / не используется |

Неизвестное значение нельзя считать совпадением. Для расхождений укажите необходимую адаптацию и её влияние на данные/пользователей. Не повторяйте уже известные вопросы и не блокируйте независимую работу; зависимую часть нельзя объявлять совместимой до проверки.

Интеграция готова в согласованном объёме, когда:

1. Все применимые критерии совпали либо адаптация реализована и проверена в целевом приложении; исключённые функции перечислены явно.
2. Пройдены анализ, тесты и сборки целевых платформ, миграции на копии базы, проверки прав и сохранности данных. Тесты каталога не заменяют тесты потребителя.
3. Для включённых внешних функций пройдена реальная цепочка на согласованном устройстве/в кабинете. Для воронок — одинаковый profileId и контекст показа в SDK и серверной конверсии, отсутствие повторного подтверждённого Revenue, корректные шаги/фильтры отчёта.
4. Зафиксированы версия/commit каталога, lockfiles, изменения схемы, секреты без значений, ограничения и порядок обновления/отката в `docs/integration-handover.md`.

Если внешние службы ещё не проверены, допустимый итог — «код интегрирован и проверен локально», а не «полная интеграция работает». Неприменимую функцию не нужно настраивать ради формального прохождения таблицы.

## Правила версии 1

- `v1.0.0` — первый выпуск каталога; тег неизменяемый, существующий тег не передвигается.
- `v1.0.x` — совместимые исправления; `v1.x.0` — совместимые дополнения. Новые обязательные требования к потребителю и несовместимые изменения публичного API/форматов требуют отдельной мажорной версии. Выпуск совместимого дополнения не разрешает автоматически отдавать старому клиенту новый type Typed Config.
- Следующая несовместимая версия Go-модуля v2 использует `/v2`; для v1 путь сохраняется. Любое изменение поддерживаемой связки PocketBase/SDK явно отражается в матрице и проверяется.
- Версия каталога не назначает версию Flutter-приложению и не публикует пакеты на pub.dev. Внутренние метаданные нативных мостов не являются способом выбора выпуска каталога.
- Наличие тега и успешных тестов не означает настройку внешних кабинетов и не заменяет условия лицензии. Лицензия по решению владельца пока не добавлена.
