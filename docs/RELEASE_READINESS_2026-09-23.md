## Исправления подготовки

- Руководство интеграции включает Typed Config и Currency Rates в общий порядок регистрации, интервью и критерии приёмки. Go- и Dart-примеры компилируются непосредственно из документа в независимых проектах-потребителях.
- Устранены противоречия по дедупликации статусов/Revenue, неопределённым отправкам и источнику аналитики пушей. Сохранён основной контракт: контексты реальных показов → SDK-события → resolve → поздний постбек с прежней атрибуцией.
- Инструкция публикации отражает все десять плагинов и подключение Flutter из полного закреплённого checkout с соседними path-зависимостями. В README восстановлена ссылка на AGENTS Typed Config; корневой AGENTS ссылается на все шесть Flutter-пакетов.
- В CI добавлены анализ/тесты Flutter, DTO Typed Config, независимые потребители, web smoke, демо-партнёр и проверка документации/состава файлов. govulncheck запускается Go-toolchain проекта, а не минимальным SDK инструмента.
- Расширены исключения Git/Docker для БД, резервных копий, локальных переопределений, приватных ключей и артефактов SDK/сборки. Клиентские Google-конфигурации example — публичные демоидентификаторы, не ключи отправителя.

## Что требует внешней проверки

Локальные HTTP-заглушки и браузерные тесты не подтверждают доставку на реальное Android/iOS-устройство, приём событий/Revenue в AppMetrica или настройки кабинета партнёра. Перед production выполните [приёмку воронки](EXPERIMENT_FUNNELS.md#приёмка-интеграции) с SDK и Post API одного приложения и `profile_id = user.id`. Аналитика кликов не имеет очереди восстановления; неопределённые постбеки требуют внешней сверки, exactly-once не гарантируется.

Workflow GitHub Actions подготовлен локально; его выполнение на GitHub возможно после отправки коммита. Лицензия и версия выпуска не назначены согласно решению владельца. Commit, push, PR и тег в рамках подготовки не создавались; подготовка не означает публикацию. Перед отправкой проверьте итоговый diff и состояние удалённой ветки по [порядку публикации](PUBLISHING.md).
