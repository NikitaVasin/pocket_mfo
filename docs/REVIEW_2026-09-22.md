# Ревью кода — 22 сентября 2026

Проверена текущая рабочая копия, включая существовавшие незакоммиченные изменения.
Основной фокус: шесть Go-плагинов, HTTP-права и служебные коллекции,
постбеки, транзакции, Flutter-сессии и открытие партнёрских ссылок.

## Исправленные проблемы

### 1. Потеря защитных атрибутов cookies — P1

`packages/dynamic_link_flutter/lib/src/dynamic_link_web_view.dart`

WebView сохранял результат `document.cookie` в SharedPreferences и затем
восстанавливал пары имя/значение через `setCookie`. Такой снимок не содержит
Secure, SameSite, исходного Path и срока действия. Восстановление могло
расширить область отправки cookie, снять Secure или вернуть уже истёкшее значение.

Удалены чтение и восстановление cookies через JavaScript. Cookies остаются
в нативном хранилище WebView. Старые копии в preferences удаляются при открытии
WebView; остальные настройки приложения сохраняются.

Совместимость: параметр `saveCooke` сохранён. Как и прежде, его значение false
не создаёт приватный WebView. Для удаления веб-сессии предусмотрен
`clearDynamicLinkWebData()`. Небезопасное продление жизни session cookies
через preferences больше не выполняется.

### 2. Загрузка страницы после очистки или закрытия WebView — P2

`packages/dynamic_link_flutter/lib/src/dynamic_link_web_view.dart`

Если очистка данных или dispose происходили во время настройки контроллера,
продолжение после await могло вызвать `loadRequest` исходной ссылки.
Это могло повторно открыть партнёрскую страницу после очистки веб-сессии.
Аналогично завершение загрузки могло обновить уже уничтоженный progress notifier.

Добавлена единая проверка mounted, признака очистки и поколения веб-данных
перед загрузкой и после асинхронных этапов. Поздняя навигация блокируется.

### 3. Принятие resolve из завершённой сессии — P2

`packages/pocket_mfo_flutter/lib/src/pocket_mfo.dart`

После HTTP-запроса проверялся только user.id. Истечение токена и последовательность
выход → вход в тот же аккаунт не отменяли результат. Слушатель authStore также
читал только текущее состояние, теряя промежуточный выход при быстрой смене сессии.

Resolve теперь проверяет действительность сессии и её поколение.
Слушатель учитывает запись из самого события authStore. Регрессионные тесты
воспроизводили принятие старой ссылки до исправления и проходят после него.

## Проверки

- `GOTOOLCHAIN=auto GOCACHE=/tmp/pocket-mfo-go-cache go test -race ./...` — успешно.
- `GOTOOLCHAIN=auto GOCACHE=/tmp/pocket-mfo-go-cache go vet ./...` — успешно.
- `npm ci`, `npx playwright install chromium` — успешно.
- `npm run test:browser` — 40 тестов, включая оба серверных стенда и темы.
- `npm run test:docker` — успешно; временный Compose project удалён тестом.
- `fvm dart analyze` — замечаний нет.
- `fvm flutter test --no-pub` для всех шести пакетов и примера — 76 тестов.
- Добавлены 8 регрессионных случаев: cookies и отмена WebView в обеих темах,
  истечение токена и быстрый выход/вход во время resolve.

Для браузера, Docker и Flutter потребовался запуск вне ограничений sandbox.
Версии Go, PocketBase и существующих зависимостей не обновлялись.
Уже используемый `webview_flutter_platform_interface` 2.15.1 явно объявлен
тестовой зависимостью для подмены нативного WebView.

В просмотренных серверных путях дополнительные подтверждённые ошибки доступа
не обнаружены. Это ревью исходников и автоматические проверки, а не полный
пентест. Последующий Go-рефакторинг, исправление лимита постбеков и результаты
сканирования зависимостей описаны в [архитектурном ревью](ARCHITECTURE_REVIEW_2026-09-22.md).

Android/iOS-устройствах и реальные запросы AppMetrica не проверялись.
