# Ревью от 24 сентября 2026

Проверены серверные плагины, клиентские пакеты, расширения админки и демонстрационные приложения. Ручное ревью сосредоточено на границах доступа, транзакциях, повторах после ошибок, снимках экспериментов и жизненном цикле клиента. Автоматические проверки охватывают весь репозиторий. Существующие незакоммиченные изменения сохранены; версии PocketBase, Go и зависимостей проекта не менялись.

## Исправленные проблемы

| Приоритет | Проблема и результат | Регрессия |
| --- | --- | --- |
| P1 | После ошибки записи гостевого секрета повторный `initialize` мог отправить запрос авторизации/регистрации без сохранённых credentials. Теперь сохранение обязательно перед каждой попыткой; идентификатор гостя сохраняется. | Два последовательных отказа хранилища без HTTP-запросов, успешный повтор и восстановление после пересоздания клиента. |
| P1 | Удалённое миграцией поле запланированной push-аудитории останавливало обработку других рассылок. Невалидный запуск теперь получает `failed` с причиной; независимые задания продолжают выполняться. | Ошибочный снимок рядом с рабочим запуском; отсутствие частичных заданий и повторной отправки. |
| P2 | `PushDevices` навсегда кэшировал ошибку чтения/записи хранилища. Кэш теперь содержит только успешно загруженные или сохранённые credentials. | Повтор после ошибок чтения и записи, отсутствие запросов до сохранения, сохранение ID/секрета после пересоздания клиента. |
| P2 | Ограниченный JSON reader принимал превышение лимита из пробелов и скрывал следующий JSON за границей чтения. Декодер MCP теперь явно отклоняет тело больше 1 MiB. | Граница лимита, превышение на байт, второй объект за лимитом, неизвестные поля. |
| P2 | Некорректный ID тестового устройства можно было сохранить в будущем push-запуске. Теперь он отклоняется до записи запуска. | Отказ без сохранения запуска. |
| P2 | Изменение User-Agent ошибочно зависело от `saveCooke`. Настройки теперь независимы. | Все сочетания cookies с включённым User-Agent, светлая/тёмная тема, проверка загрузки URL. |
| Документация | Подсказки Partner Links отрицали существующую дедупликацию Revenue и подтверждённых событий. Тексты приведены в соответствие с квитанциями доставки и обработкой неопределённого результата. | Сверка с `delivery.go` и его тестами; браузерные сценарии настроек. |

Для push отдельно проверен откат при ошибке финального сохранения запуска: задания и cooldown не остаются, статус сохраняет возможность повторной попытки. Ошибки хранения не превращаются в окончательный отказ валидации.

## Правки интерфейса по ходу ревью

- Категории Dynamic Link представлены вкладками. Новая категория активируется сразу; переключение сохраняет черновик. Доступны стрелки, Home/End; после удаления выбирается оставшаяся категория.
- Селекторы Dynamic Link, Partner Links и Push используют штатный компонент PocketBase с поиском и выпадающим списком. Убрано смешение этих компонентов с системными HTML-списками.
- Для узкого экрана исправлены ограничения ширины сетки push и переносы подписей. Проверены расположение открытых списков и отступ до заголовка WebView.
- Штатные формы записей, Singleton, Variants, блокировки Schema Lock и серверные проверки сохранены.

## Проверки

- `go test -race ./...`, `go vet ./...`, `go build ./...`, `go mod verify`.
- `govulncheck v1.8.0` под Go 1.27: уязвимых вызываемых символов и импортируемых пакетов не найдено. На уровне транзитивного модуля отмечен GO-2026-5932 для неиспользуемого `golang.org/x/crypto/openpgp`; обновление зависимостей не выполнялось.
- FVM: lockfile проверен через `pub get --enforce-lockfile`, анализ без замечаний, 93 Flutter-теста и 3 теста доменного Dart-пакета.
- Анализ и smoke генерируемых Typed Config DTO; независимая компиляция примеров интеграции Go/Flutter.
- Браузерные сценарии двух стендов, светлая/тёмная темы, ширины 390/1280 px, изменения и сохранение форм, клавиатура, права доступа.
- Docker smoke, стенд демонстрационного партнёра, сборка Flutter web и web smoke.
- Проверка структуры репозитория, форматирования Go и `git diff --check`.

## Границы проверки

Это ревью и регрессионные проверки, а не доказательство отсутствия всех дефектов. Реальная доставка через AppMetrica/FCM/APNs и поведение WebView на физических устройствах в этом проходе не проверялись; серверные тесты используют заглушки, Flutter-тесты — платформенные адаптеры. Нативные Android/iOS-файлы не изменялись.

Существующее ограничение WebView сохранено: `saveCooke=false` не создаёт приватное хранилище cookies. Нативная веб-сессия очищается через `clearDynamicLinkWebData()`; контракт описан в README Flutter-адаптера. Изоляция сессий по категориям требует отдельного платформенного решения.

Массовая перестройка пакетов не потребовалась. Рефакторинг ограничен обработкой ошибок push и кэшем credentials, а UI использует готовые компоненты PocketBase.
