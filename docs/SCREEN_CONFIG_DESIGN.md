# Типизированные экранные конфигурации

Реализован плагин [Typed Config](../plugins/typedconfig/README.md). Актуальное требование пользователя: в админке только понятные формы и карточки items, без просмотра или редактирования JSON.

## Реализованная модель

Обычная коллекция содержит поле typedConfig с версионированной схемой. Поддерживаются примитивы, перечисления, вложенные объекты, массивы, переиспользуемые типы и ссылки на записи с типизированным mapping. Схема задаётся Go-кодом/миграцией, интерфейс строится автоматически.

Для совместимости с нативным Records API выбран JSON-список + скрытые реальные relation-поля, вместо первоначально предложенной отдельной таблицы screen_items. JSON и все связи сохраняются одной транзакцией. При удалении исходной строки удаляются содержащие её блоки, включая вложенные зависимости. Источники остаются общими и не удаляются вместе с блоками.

Приложению выдаётся готовая проекция полей с проверкой ViewRule источников. Есть генератор типизированных Dart DTO. Variants подписывает ревизию собранного материала для дальнейшей атрибуции событий; сами показы отправляет приложение.

## Редактор

Встроен в обычную форму записи PocketBase. Есть карточки с названием и кратким содержимым, добавление по типу, вложенные формы, переключатели необязательных полей, штатный выбор связанных записей, дублирование, удаление, кнопки перестановки, drag-and-drop и поиск. Сохранение/отмена/черновики используют штатную форму. Табличный просмотр тоже показывает сводку блоков вместо JSON.

Демонстрация: example → demo_screen_configs → Главная витрина. Светлая/тёмная темы, узкий экран и Schema Lock проверяются браузерным тестом.

## Границы текущей реализации

- Визуального конструктора самих схем и точного Flutter-preview нет; новые компоненты реализуются во Flutter.
- Нет произвольных query-source, SQL/JS в mapping, автоматического соединения конфликтующих слоёв или самостоятельного редактора экспериментов.
- Для независимых тестов приложение явно объединяет конфигурации дизайна/офферов/порядка/переходов и передаёт их контексты по [контракту воронок](EXPERIMENT_FUNNELS.md).
- Конфигурация сохраняется целиком со штатной конкурентной семантикой PocketBase; отдельного протокола разрешения конфликтов авторов нет.
- При удалении источника блоки удаляются сервером; общего диалога предварительного просмотра каскада для всех штатных экранов PocketBase пока нет. Форма ссылки явно объясняет поведение удаления.
- Изменение источника проявляется при следующем чтении; само по себе оно не отправляет realtime update родителя. Удаление зависимого блока изменяет родительскую запись.

Полный контракт, ограничения и пример подключения находятся в [README плагина](../plugins/typedconfig/README.md).
