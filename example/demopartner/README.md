# Демо партнёр

Локальный кабинет для проверки цепочки «приложение → партнёр → постбек → Pocket MFO → AppMetrica». Ориентир сценария — заявки, ожидание/холд, подтверждение и выплаты в [кабинете Rafinad](https://rafinad.io/faq/). Это самостоятельный симулятор; его поля постбека описаны ниже, совместимость с API Rafinad не заявляется.

## Запуск вместе с example

```sh
docker compose -f example/compose.yaml up -d --build
```

- PocketBase: http://127.0.0.1:8090/_/
- Кабинет партнёра: http://127.0.0.1:8091/
- Flutter-пример: [инструкция](../../examples/partner_links_app/README.md).

В example миграция настраивает провайдера `demo`, его поля постбека и ссылку `demopartner0001` на `http://127.0.0.1:8091/click`. Существующие Application ID и Post API key не меняются. Если ключи ещё не введены, задайте **ваши настоящие** Application ID и Post API key в «Партнёрских ссылках» PocketBase; Flutter должен активировать SDK с клиентским ключом того же приложения и user.id. AppMetrica работает напрямую, заглушки в Compose нет.

Кабинет партнёра заранее настроен на `http://pocketbase:8090/api/partnerlinks/postbacks/demo`. Это внутренний адрес Compose, браузер его не открывает. Секрет `public-demo-postback-secret` совпадает с демонстрационным провайдером. Если вы меняли секрет или поля провайдера, согласуйте их в обоих кабинетах. Ключ AppMetrica партнёру не передаётся.

Для изменения внешних адресов при **первом** создании базы:

```sh
DEMO_PUBLIC_URL=http://10.0.2.2:8090 \
DEMO_PARTNER_PUBLIC_URL=http://10.0.2.2:8091 \
docker compose -f example/compose.yaml up -d --build
```

`10.0.2.2` подходит Android-эмулятору. Для физического устройства используйте адрес доступного хоста и настройте публикацию портов отдельно: по умолчанию оба порта привязаны к loopback. Для изменения портов хоста — `POCKETBASE_PORT` / `DEMO_PARTNER_PORT`. После первого запуска меняйте Base URL в PocketBase и URL поля `partner_links.link` вручную: одноразовая миграция не перезаписывает отредактированные ссылки. Старый стандартный URL `https://example.com/offer` обновляется автоматически.

## Сценарий

1. Запустите Flutter-пример и откройте демонстрационный оффер. Resolve создаст конверсию в Pocket MFO; серверный редирект передаст токен партнёру.
2. Партнёр сохранит переход и ответит `302 https://www.google.com/`. Публичный маршрут — `GET /click?subid=TOKEN`. Повтор того же токена оставляет ту же заявку. HEAD не создаёт запись.
3. Откройте кабинет, нажмите «Обновить», затем «Изменить» у заявки. Выберите «Новая заявка», «Холд», «Подтверждено» или «Отклонено», сумму вознаграждения и валюту.
4. «Сохранить и отправить» сохраняет статус у партнёра и посылает постбек. Колонка доставки показывает результат: 200 — доставлен, иной HTTP-код или ошибка соединения — требуется проверка получателя. Статус партнёра сохраняется даже при отказе получателя.
5. Проверьте запись `conversations` в PocketBase и заказы в приложении. Для доходов включите Revenue у провайдера `demo` и выберите оплачиваемый статус: hold или approved. Не отправляйте оба как одну выплату.

Настройки постбеков позволяют выбрать URL, GET / POST JSON / POST form, секрет в query, заголовке или body. Пустой секрет сохраняет прежний. GET с секретом в body запрещён. Поля фиксированы и уже настроены в example:

| Поле | Значение |
| --- | --- |
| subid | Токен выданной ссылки |
| status | lead / hold / approved / rejected |
| lead_id | Постоянный ID заявки партнёра |
| event_id | ID конкретного изменения |
| timestamp | Время изменения в Unix seconds |
| amount, currency | Вознаграждение вебмастера, например 100.50 и RUB |

Переход не отправляет lead автоматически. Статус lead отправляйте отдельно, если он нужен в воронке. Повтор сохраняет event_id и timestamp исходной отправки. Автоматических повторов нет; успешный повтор может создать дубли событий и Revenue в AppMetrica. События старше 14 дней получатель отклонит. Ограничения первой сессии профиля AppMetrica описаны в [Partner Links](../../plugins/partnerlinks/README.md).

## Данные и ограничения

Конверсии и настройки хранятся атомарным JSON-снимком в отдельном volume `partner_data`; перезапуск сохраняет их. База PocketBase остаётся в `pb_data`. Не удаляйте volumes ради обновления. Кабинет без авторизации рассчитан только на локальную разработку; не публикуйте его в интернете. Он не собирает ФИО/телефоны и не использует реальные данные заявок. URL назначения всегда фиксирован — Google.

Без Docker:

```sh
GOTOOLCHAIN=auto go run ./example/demopartner
```

По умолчанию порт 8091, файл `./pb_data/demo-partner.json`, постбек на `127.0.0.1:8090`. Переопределение: `PARTNER_ADDR`, `PARTNER_DATA`, `POSTBACK_URL`. Настройки из сохранённого файла имеют приоритет над начальными значениями окружения.

Проверки: `go test -race ./example/demopartner`, `npm run test:partner`, `npm run test:docker`. Тесты используют только временные данные и локального получателя постбеков, не отправляют события с реальными ключами.
