# Pocket MFO Flutter

Единая интеграция PocketBase, AppMetrica, экспериментов, партнёрских ссылок и опциональных пушей для Android/iOS. Нижние пакеты остаются самостоятельными. Запускаемый пример — [partner_links_app](../../examples/partner_links_app).

## Подключение

Добавьте пакет в зависимости приложения. Создайте один экземпляр на время работы приложения, сохранив переданный PocketBase и его authStore:

```dart
import 'package:flutter/widgets.dart';
import 'package:pocketbase/pocketbase.dart';
import 'package:pocket_mfo_flutter/pocket_mfo_flutter.dart';

final navigatorKey = GlobalKey<NavigatorState>();
final pb = PocketBase('https://api.example.com');
late final PocketMfo mfo;

Future<void> initializeIntegration() async {
  WidgetsFlutterBinding.ensureInitialized();
  mfo = PocketMfo(
    pocketBase: pb,
    authCollection: 'users',
    appMetricaConfig: const AppMetricaConfig('APPLICATION_SDK_API_KEY'),
    storage: const SecureSessionStorage(),
    onError: (error, stack) { /* диагностика без токенов и паролей */ },
  );
  await mfo.initialize();
}
```

SDK API key — клиентский ключ приложения. Post API key задаётся только в серверных настройках Partner Links. `profileId` всегда равен `users.id`; выбирать поле или записывать SDK ID в пользователя не нужно. Не активируйте SDK отдельно: при подключении пушей Messaging использует уже активированную аналитику. Прямой вызов `AppMetrica.reportEvent*` обходит обогащение, автоматические события SDK не дополняются.

```dart
await mfo.reportEvent('apply_button', parameters: {'button': 'apply'});
await mfo.refreshExperiments(); // например, после обновления контента
await mfo.signIn('user@example.com', 'password');
await mfo.logout(); // удаляет текущую сессию и создаёт НОВОГО гостя
final result = await mfo.resolvePartnerLink(linkId: 'offer_record_id');
// Или сразу открыть, когда context смонтирован:
await mfo.openPartnerLink(context, linkId: 'offer_record_id');
// При окончательном завершении владельца:
await mfo.dispose();
```

Методы авторизации и ссылок выбрасывают ошибки (`ClientException`, `PocketMfoAuthRequired`); приложение показывает подходящий экран/повтор. Каждое открытие получает новый токен. Полученный публичный URL загружается непосредственно адаптером без предварительного редиректа и второго события клика.

## Гости и хранение

Используется стандартный PocketBase `create()` + `authWithPassword()`. Отдельного Go-плагина, маршрута гостевого входа и таблицы привязок нет. Это два штатных запроса, а не общая серверная транзакция. До первого запроса пакет сохраняет случайный ID (15 символов) и криптографически стойкий пароль (48 символов). Повтор после потери ответа использует те же данные. Уникальный ID исключает создание двух записей для одной пары учётных данных; успешное создание при прерванном входе восстанавливается следующим входом.

В `users` необходимо разрешить парольную авторизацию по `id` (с уникальным индексом), сделать email необязательным и задать узкое CreateRule только для гостевых записей. Обычная регистрация не должна открываться через пустое правило. Пример такой миграции: [1789948806_demo_guests.go](../../example/migrations/1789948806_demo_guests.go). Она запрещает гостю устанавливать email, verified, name и tier; Variants вычисляет content_bucket на сервере. Прикладные доверенные значения устанавливайте хуками Go перед сохранением записи. Не передавайте секреты или привилегированные поля через `guestFields`: это обычные клиентские данные, проверяемые API rules. AuthRule и MFA продолжают действовать; для обычного входа с MFA завершайте штатный процесс через тот же PocketBase.

Сессия и пароль гостя хранятся одним значением в `flutter_secure_storage`, раздельно по URL сервера и auth-коллекции. Переданный authStore не заменяется. Для iOS используется Keychain с доступом после первого разблокирования на этом устройстве; настройте Keychain/entitlements и Android backup по инструкции установленной версии `flutter_secure_storage`. В тестах и web-примере используется явный `MemorySessionStorage`, который ничего не сохраняет после перезапуска.

Действующая сессия восстанавливается через authRefresh. Истёкшая гостевая сессия восстанавливается паролем. Сбой сети не создаёт другого пользователя: неистёкшая сохранённая сессия может работать офлайн, истёкшая возвращает ошибку. Недействительная сессия обычного аккаунта требует входа либо явного `logout()` для нового гостя. После потери локального секрета восстановить того же гостя нельзя. Профили и заказы между гостем и обычным аккаунтом автоматически не объединяются.

## Эксперименты

`GET /api/variants/me` возвращает `items` и готовую карту. Она загружается при инициализации, смене пользователя, возвращении приложения на передний план и явном обновлении:

```json
{"button":"apply","experiments":{"offers":"premium/checkout_test/B","dynamic_link_settings":"default"}}
```

Ключ — имя коллекции; значение — стабильные ключи `variant/experiment/group`, либо вариант без активного эксперимента. Отключённые Variants исключаются. Снимок хранится только в памяти текущей сессии, отправка события не делает HTTP-запросов. Обновления объединяются, ограничены двумя секундами, запоздалый ответ предыдущего пользователя отбрасывается. Пока идёт запрос или при ошибке используется последний успешный снимок этого пользователя. Если его ещё нет, ключ `experiments` отсутствует; успешный пустой результат даёт `{}`. Ошибки обновления передаются в `onError` и не блокируют аналитику.

Параметр `experiments` зарезервирован: пользовательское значение заменяется/удаляется, исходная карта не меняется. Смена профиля SDK и отправка событий через фасад выполняются последовательно. Сервер Partner Links независимо сохраняет карту при выдаче ссылки и использует её в кликах, постбеках и Revenue; будущие изменения назначений не меняют прошлую конверсию.

## Пуши

Для серверного [Push-плагина](../../plugins/push/README.md) задайте `registerDevices: true` в `PocketMfoPushConfig`. Фасад регистрирует AppMetrica Device ID, обновляет разрешение и активность, отключает прежнюю привязку перед сменой аккаунта, передаёт открытия кампаний. Секрет установки хранится отдельно от сессии. При сетевой ошибке отключения смена аккаунта не продолжается; повторите после восстановления связи. После ручного изменения разрешения вызовите `mfo.refreshPushDevice()`. Для условий по версии задавайте `AppMetricaConfig.appVersion`. Без серверного плагина оставьте `registerDevices: false` (по умолчанию).

Передайте `PocketMfoPushConfig(navigatorKey: navigatorKey, onNavigate: ...)` и тот же ключ корневому `MaterialApp`/router. `onNavigate` обрабатывает прикладные пути, например `/orders`. Firebase/APNs и нативную часть настройте по [Messaging](../app_messaging_flutter/README.md). Пуши опциональны. Для автоматического запроса разрешения передайте `requestPermissionOnStart: true` в `PocketMfoPushConfig`: запрос выполняется после инициализации Messaging один раз на экземпляр, включая параллельные вызовы `initialize`. По умолчанию параметр `false`; вручную доступен `mfo.messaging?.requestPermission()`. В запускаемом примере автоматический запрос включён.

Действие холодного запуска ждёт авторизации и готового Navigator. Партнёрские действия используют существующий [PushLinkResolver](../push_links_flutter/README.md). `dispose()` удаляет подписки и запрещает отложенную навигацию. Не вызывайте методы изменения SDK профиля через Messaging параллельно фасаду.

## Проверки и ограничения AppMetrica

`PocketMfoAnalytics`, `SessionStorage` и `MessagingDriver` подменяются для тестов и браузерного примера. Нативные SDK предназначены для Android/iOS. Запуск тестов: `fvm flutter test packages/pocket_mfo_flutter/test`.

[Ограничения Post API](https://appmetrica.yandex.ru/docs/ru/mobile-api/post/restrictions): профиль должен быть известен SDK; назначенному в первой и единственной сессии профилю может потребоваться повторный вход. Отправка `user.id` не устраняет это ограничение. Серверные события старше 14 дней не передатируются. HTTP 200 означает приём API, а не немедленное появление в отчёте. Product Flow в этой интеграции не используется; воронка строится по `offer_*`, доходы — через Revenue выбранного статуса провайдера.

Регистрация пуш-устройства использует числовой `DeviceIdHash` из `AppMetrica.requestStartupParams`, соответствующий `appmetrica_device_id` в Push API. Не подменяйте его обычным `AppMetrica.deviceId` (hex). Получение ограничено 10 секундами; ошибки направляются в `onError`, повтор возможен через `refreshPushDevice()` или при возврате в приложение. Flutter-пример выводит в debug только категорию ошибки, HTTP-статус и стек, без токенов и идентификаторов.
