# AppMetrica

Общие настройки и HTTP-доступ к AppMetrica для Partner Links и Push. В коде достаточно закрепить **Application ID и OAuth-токен**. При запуске HTTP модуль сам получает SDK API key и Post API key из Management API. Вкладка **AppMetrica** показывает ID, публичный SDK-ключ и признаки наличия секретов. Секреты не возвращаются браузеру. SDK API key здесь справочный: клиентское приложение по-прежнему инициализирует SDK своей конфигурацией.

```go
applicationID := int64(1234567)
oauthToken := os.Getenv("APPMETRICA_PUSH_OAUTH_TOKEN")
appmetrica.Register(app, appmetrica.Options{
    Managed: &appmetrica.ManagedConfig{
        ApplicationID: &applicationID,
        OAuthToken: &oauthToken,
    },
})
// Затем partnerlinks.Register / push.Register, последним — Schema Lock.
```

Импорт: `github.com/NikitaVasin/pocket_mfo/plugins/appmetrica`. Register вызывается до Bootstrap/Start, перед потребителями. Ненулевой указатель Managed закрепляет поле, включая пустое значение. Чтобы отсутствующий ключ можно было заполнить в админке, не задавайте указатель. Регистрация копирует значения. Остальные ключи не требуется вводить вручную. Если автоматическое получение не удалось, сервер запускается с предупреждением; повторите «Подключить AppMetrica» в админке. Без закрепления полей в коде UI запрашивает OAuth-токен и Application ID (при единственном приложении ID определяется автоматически, при нескольких нужен явный выбор). Неудачное подключение не меняет настройки.

Имена событий задаются через Go (полная карта `DefaultConfig().EventNames`), в HTTP не редактируются.

`Load(app)` возвращает эффективный Config доверенному серверному коду. `Configure(app, config)` атомарно сохраняет незакреплённые параметры; передавайте актуальную Version. Пустые секреты сохраняют прежние значения. `LockAdminConfig` запрещает весь HTTP PUT. Значения Managed, кроме Application ID для контроля привязок, не записываются в базу. Сохранённые оператором секреты лежат в защищённой служебной коллекции `appmetrica_config`, без дополнительного шифрования; доступ к базе и бэкапам должен оставаться ограниченным.

## Готовность и проверка

- **События и доходы:** нужны Application ID и Post API key. Заполненность не подтверждает действительность ключа. Если OAuth позволяет прочитать `import_token`, проверка сверяет Post API key с ним. Совпадение подтверждает ключ, но не приём событий/доходов; синтетические события и Revenue не создаются.
- **Push API:** нужны Application ID и OAuth-токен. Проверка читает сведения о приложении и список групп. Успех не подтверждает права на отправку, конфигурацию Firebase/APNs или доставку на устройство.
- **Чтение аналитики:** проверка запрашивает отчёт. Ошибки отделены от нулевых метрик.

`Status(config)` не обращается к сети. `Plugin.Check(ctx, config)` использует только GET и ограниченные таймауты/размеры ответов. Результат проверки не сохраняется как бессрочная гарантия: UI сбрасывает его после правки и перезагрузки. Ответ на проверку отклоняется, если конфигурация изменилась во время запроса.

API для суперпользователя: `GET/PUT /api/appmetrica/admin/config`, `POST /api/appmetrica/admin/check`, `POST /api/appmetrica/admin/connect`. Последний получает ключи из внешнего API только чтением и атомарно сохраняет локальные настройки. Эти точные маршруты разрешены Schema Lock; CRUD служебной коллекции, её схема, truncate и чтение секретов через Records API запрещены.

## Перенос существующих настроек

При первом запуске с модулем настройки импортируются из Partner Links и Push в одной транзакции. Разные ненулевые Application ID (в том числе закреплённый новым модулем ID) блокируют перенос. Сначала согласуйте идентификаторы и привязки; модуль не выбирает один автоматически. После переноса оба плагина читают общий модуль; изменять AppMetrica через их Configure/API нельзя.

Старые данные конфигурации остаются неактивными для совместимости, но не переимпортируются при следующих стартах. Старые поля Managed/OAuthClientID в потребителях предназначены только для перехода: перенесите их в `appmetrica.ManagedConfig` и удалите из опций потребителей. Для новых приложений всегда регистрируйте общий модуль. Без него прежний Go-контракт работает для обратной совместимости; новых редакторов AppMetrica в потребителях нет.

Push регистрирует защиту идентификатора: существующие устройства и незавершённые запуски блокируют смену Application ID как через Configure, так и через изменение кода при перезапуске. Расширения могут регистрировать собственные проверки через `GuardApplicationChange` до Bootstrap.

## Firebase

В публичной документации не найден поддерживаемый метод загрузки Firebase service account JSON через OAuth. Ключ пока загружается в кабинете AppMetrica; модуль не принимает и не хранит этот файл. [Официальная инструкция](https://appmetrica.yandex.ru/docs/ru/sdk/android/push/android-settings), [Push API](https://appmetrica.yandex.ru/docs/ru/mobile-api/push/all-resources).

Автоматическое получение требует права на чтение ключей выбранного приложения. Источники: [информация о приложении](https://appmetrica.yandex.ru/docs/ru/mobile-api/management/applications/getapplication), [список приложений](https://appmetrica.yandex.ru/docs/ru/mobile-api/management/applications/getapplicationslist).
