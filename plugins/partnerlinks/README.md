# Partner Links

Для связи заявок с push-рассылками передайте `Options.Attribution: push.Attribution` из [Push-плагина](../push/README.md). Callback вызывается при выдаче ссылки, результат сохраняется в `clickData.push` и сохраняется при поздних постбеках. Без callback поведение не меняется.

Партнёрские ссылки и серверные конверсии AppMetrica для PocketBase v0.40.4 / Go 1.27. Админка: **Партнёрские ссылки** в верхней панели.

## Конфигурация через Go и блокировка админки

```go
// types.Pointer — github.com/pocketbase/pocketbase/tools/types
rafinad := partnerlinks.RafinadNew("rafinad", os.Getenv("RAFINAD_POSTBACK_SECRET"))
rafinad.SendRevenue = true // необязательно; по умолчанию выключен
rafinad.RevenueStatus = "approved"

partnerlinks.Register(app, partnerlinks.Options{
    AuthCollections: []string{"users"},
    LockAdminConfig: true, // вся страница настроек доступна только для просмотра
    Managed: &partnerlinks.ManagedConfig{
        BaseURL: types.Pointer("https://api.example.com"),
        ApplicationID: types.Pointer(int64(1234567)),
        PostAPIKey: types.Pointer(os.Getenv("APPMETRICA_POST_API_KEY")),
        OpenTTLSeconds: types.Pointer(int64(86400)),
        PendingRetentionDays: types.Pointer(14),
        ConversionRetentionDays: types.Pointer(0), // бессрочно
        EventNames: map[string]string{
            "click": "offer_click", "lead": "offer_lead",
            "approved": "offer_approved", "hold": "offer_hold",
            "rejected": "offer_rejected",
        },
        Providers: []partnerlinks.Provider{rafinad},
    },
})
```

`Managed` можно заполнить частично. Ненулевой указатель фиксирует поле, включая явное значение `0` или пустую строку. В `EventNames` фиксируются только переданные ключи. Каждый переданный провайдер фиксируется целиком по ID: его нельзя изменить или удалить через `Configure` или HTTP. Остальные провайдеры можно добавлять и редактировать. Настройки проверяются при Bootstrap и перед запуском HTTP; ошибочная конфигурация не запускается.

`Load` возвращает сохранённые настройки с наложенными значениями из кода. Для изменения остальных настроек берите актуальный результат `Load`, меняйте нужное поле и передавайте в `Configure`. Значения `Managed` хранятся только в памяти процесса; после удаления настройки из кода снова действует её прежнее значение из БД или значение по умолчанию. Новый провайдер, заданный только в коде, исчезнет после удаления из кода — сначала перенесите его конфигурацию, если его используют ссылки. Все экземпляры сервера должны запускаться с одинаковой конфигурацией.

`LockAdminConfig` независимо запрещает весь `PUT /api/partnerlinks/admin/config` (403 даже для суперпользователя). Поля и кнопки редактирования на странице disabled, просмотр инструкции и секрета партнёра доступен. Доверенный Go-код может вызывать `Configure` для настроек, не закреплённых в `Managed`. Записи коллекции `partner_links` остаются редактируемыми.

## Пресет Rafinad New

В новом или существующем провайдере выберите **«Пресет партнёра → Rafinad New»**. Шаблон ссылки, поля и статусы заполнятся автоматически; для пустого секрета создаётся случайное значение. ID, название и уже введённый секрет сохраняются. Выбор пресета заменяет предыдущие сопоставления. На странице появится инструкция с адресом вашего сервера и секретом.

Из Go используйте `partnerlinks.RafinadNew(id, secret)` как обычный `Provider` в `Configure` или как фиксированный провайдер в `Options.Managed`. `ProviderPresets()` возвращает каталог пресетов с независимыми картами настроек. Результат фабрики можно изменить, например включить Revenue. Если меняете транспортные поля или статусы, настройте кабинет соответствующим образом; стандартная UI-инструкция в таком случае заменяется подсказкой о восстановлении пресета.

В кабинете **new.rafinad.io → Инструменты → Постбеки → Создать**:

1. Укажите название, метод **GET** и ссылку `https://YOUR_SERVER/api/partnerlinks/postbacks/PROVIDER_ID`.
2. В фильтрации выберите оффер и источник, либо включите глобальный постбек. «Всегда отправлять глобальный постбек» включайте, если он нужен и при наличии отдельного постбека оффера. Не дублируйте отправку на один адрес.
3. Отметьте все четыре статуса и задайте маппинг: **В ожидании → 1**, **В холде → 2**, **Отклонено → 3**, **Одобрено → 4**.
4. В «Параметры» добавьте строки из таблицы. В «Константы» добавьте имя **secret** и значение секрета вашего провайдера.
5. Сохраните постбек. В `partner_links` выберите этого провайдера и укажите исходную ссылку потока Rafinad в `link`. При переходе сервер сам добавит `p_click_id` с токеном.

| Имя параметра | Макрос Rafinad |
| --- | --- |
| `p_click_id` | `{p_click_id}` |
| `status` | `{status}` |
| `order_id` | `{order_id}` |
| `publisher_commission` | `{publisher_commission}` |
| `currency` | `{currency}` |

События: `1 → lead`, `2 → hold`, `3 → rejected`, `4 → approved`. Доход — комиссия `publisher_commission`, а не сумма заказа `order_total`. Revenue по умолчанию выключен, выбранный статус начисления — `approved`. Даты Rafinad строковые, поэтому пресет не сопоставляет их с Unix timestamp: используется время получения постбека. Для проверки сначала откройте ссылку из приложения и используйте её настоящий `p_click_id`; произвольный тестовый токен не создаёт конверсию.

## Подключение

```go
options := partnerlinks.Options{
    AuthCollections: []string{"users"}, // имена или ID разрешённых auth-коллекций
}
variants.Register(app)
singleton.Register(app)
dynamiclink.Register(app)
partnerlinks.Register(app, options)
schemalock.Register(app)
```

Вызвать до Bootstrap/Start. Auth-коллекции должны существовать после миграций к моменту Start. Все опубликованные конфигурации Variants для auth-коллекции пользователя подключаются автоматически. Без плагина Variants карта пуста. `Options.VariantCollections` устарело и игнорируется. В example настроены `users`, `demo_offers` и `dynamic_link_settings`.

Шифрование и серверные AES-ключи больше не используются. При каждом resolve создаётся запись в `conversations`, а в ссылку помещается случайный токен: 32 байта из криптографического генератора, 43 символа base64url. Токен не содержит JSON и не является ID записи. В базе хранится только его SHA-256 для поиска, поле скрыто из Records API.

При переходе со старой версии удалите из подключения `CollectConversations`, `ActiveKeyID`, `Keys` и замените `OptionsFromEnv` на `Options`, как выше. Переменные `PL_ACTIVE_KEY_ID`/`PL_KEYS` больше не нужны. Схема `conversations` обновляется атомарно; существующие заказы, ID и связи сохраняются. Старые зашифрованные ссылки и постбеки по ним больше не принимаются — приложение должно запросить новые ссылки. Исторические записи без сохранённого снимка клика остаются в списке заказов; восстановить их прежний токен невозможно.

## Настройки и таблица ссылок

В разделе настроек задайте публичный URL сервера, числовой **Application ID** и **Post API key** из AppMetrica. Это один аккаунт приложения AppMetrica на сервер. Секрет партнёра виден суперпользователю в настройках и доступен для копирования. Post API key после сохранения не возвращается браузеру. Пустое поле секрета при следующем сохранении сохраняет прежнее значение.

AppMetrica profileId всегда равен PocketBase `user.id`. Приложение задаёт этот ID SDK; [pocket_mfo_flutter](../../packages/pocket_mfo_flutter/README.md) делает это автоматически после авторизации. Выбор поля профиля и API profile-fields удалены. Существующие пользовательские поля и старые данные конверсий сохраняются; серверные события используют сохранённый userId, включая старые конверсии.

Страница зарегистрирована через UI API в верхней панели PocketBase (`#/partner-links`). Штатная боковая панель Settings не изменяется. Старые закладки настроек перенаправляются на новую страницу.

Срок открытия новой ссылки — `openTtlSeconds`, по умолчанию 86400 секунд (1 сутки), максимум 1 год. Время открытия фиксируется при выдаче. Поздний постбек допускается независимо от истечения срока открытия, пока хранится конверсия.

Сроки хранения настраиваются в днях:

- `pendingRetentionDays`: **14** по умолчанию, от момента выдачи ссылки. `pending` означает, что от партнёра ещё не получено ни одного статуса.
- `conversionRetentionDays`: **0** по умолчанию — бессрочно. Отсчитывается от последнего фактического изменения статуса на сервере. Повтор того же статуса и устаревший постбек этот срок не продлевают. Прямые `hold`, `approved` и `rejected` тоже относятся к этой группе; синтетический `lead` не создаётся.

В обоих полях `0` означает бессрочное хранение; допустимо 0–36500 дней. Сроки применяются и к существующим записям. Очистка запускается ежечасно через PocketBase Cron; доверенный Go-код может вызвать `partnerlinks.Cleanup(app)`. Просроченная запись не принимает открытия и постбеки уже до физического удаления (410). После удаления токен неизвестен серверу (400), запись по постбеку не создаётся заново. Очистка удаляет также заказ из истории пользователя. Для старых заказов начало срока — время последнего события, при его отсутствии — время миграции.

Провайдер содержит:

- стабильный `id`, название и `urlTemplate`;
- `maxTokenLength`: лимит партнёра на clickData, 0 означает отсутствие ограничения провайдера. Текущий токен всегда занимает 43 ASCII-символа; меньший лимит отклоняет выдачу без создания записи;
- секрет минимум 16 байт, `secretLocation` (`query`/`header`/`body`) и `secretName`;
- сопоставления полей постбека, статусов и дополнительных параметров.

Шаблоны:

```text
{url}?subid={clickData}
{url}&subid={clickData}
https://tracking.example/go?destination={url}&subid={clickData}
```

В первых двух вариантах query-параметры объединяются с исходным URL; совпадающие ключи заменяются параметрами шаблона. Fragment исходного URL сохраняется. При вложенном `{url}` исходный URL query-кодируется один раз. `{clickData}` допустим в пути или query; в host/fragment запрещён. Поддерживаются только HTTP(S), неизвестные placeholders отклоняются. Секрет постбека не включается в публичный URL.

Обычная коллекция `partner_links` содержит `name`, `provider` (ID провайдера), `active` и `link` типа [Dynamic link](../dynamiclink/README.md) — URL вместе с параметрами открытия. Создавайте и редактируйте записи через штатный редактор коллекции. Поле `provider` предлагает сохранённых провайдеров по названию и ID, с поиском; в записи сохраняется ID. Список обновляется при открытии формы. В настройках плагина списка ссылок нет. По умолчанию чтение доступно авторизованным, запись — суперпользователям. Настройте ViewRule в миграции либо подключите Variants к этой коллекции, если доступ к ссылкам должен зависеть от аудитории. В прикладной коллекции офферов можно создать relation на `partner_links`.

**Правило доступа оффера автоматически не наследуется связанной ссылкой.** Ограничения выдачи задаются у `partner_links`. Запрос разрешён только несистемному пользователю из `Options.AuthCollections`; суперпользователю нужен вход от имени обычного пользователя.

`link` содержит обязательный `url` и параметры DynamicLink: `mode` (`appView`/`view`/`browser`), `saveCooke`, `changeClient`, `showLoader`, `openUrlsInBrowser`, `skipWarningDialog`, необязательные `warningDialog: {title, content}`, `title`, `trackName`. Без настроек используется WebView, cookies и loader включены, прочие флаги выключены. В ответе resolve исходный link.url заменяется URL серверного редиректа. Если настроена `dynamic_link_settings`, сервер применяет режим и предупреждение выбранного пользователю набора Variants. Эта коллекция автоматически входит в текущие назначения; для атрибуции показа передайте её контекст вместе с контекстами экрана.

При запуске существующая коллекция автоматически переносится с `url` + `opening` на `link` типа `dynamicLink`. URL, явные выключенные переключатели, режим, предупреждение и прочие параметры сохраняются. Перенос данных и изменение схемы выполняются в одной транзакции; некорректные старые значения или несовместимая схема останавливают миграцию без частичных изменений. Прикладные поля, ID записей и связи сохраняются. После перехода записи через Records API создаются с `link: {"url": "https://partner.example/offer"}`; старые поля удалены.

## HTTP API

### Выдать ссылку

`POST /api/partnerlinks/links/{id}/resolve`, с PocketBase Authorization и JSON:

```json
{}
```

Без контекста показов тело запроса — пустой объект или отсутствует. Для воронки передайте `{"exposureTokens":["SIGNED_TOKEN"]}` из `variantContext` реально показанных записей; Flutter принимает их через параметр `exposures`. Сервер проверяет подпись и пользователя, а не доверяет произвольным назначениям. См. [контракт воронок](../../docs/EXPERIMENT_FUNNELS.md). Profile ID равен ID авторизованного пользователя. `profileId`, `device`, `userId`, назначения экспериментов и неизвестные поля отклоняются. Данные устройства повторно не отправляются.

Ответ:

```json
{
  "clickId":"random-id",
  "expiresAt":"2026-09-22T12:00:00Z",
  "link":{
    "url":"https://links.example/api/partnerlinks/r/RANDOM_OPAQUE_TOKEN",
    "mode":"appView","saveCooke":true,"changeClient":false,
    "showLoader":true,"openUrlsInBrowser":false,"skipWarningDialog":false
  }
}
```

Выдача не отправляет событие. После проверки активности, ViewRule, шаблона, длины токена и Dynamic Link сервер сохраняет запись `conversations` со статусом `pending`. Поле `clickData` хранит случайный clickId, userId/auth-коллекцию, Application ID, linkId/providerId, время выдачи, срок открытия и готовую карту `analyticsExperiments` вместе со снимком `variants.Decision` для настроенных коллекций соответствующей auth-коллекции. В URL передаётся только случайный токен для поиска этой записи. `Resolve` не создаёт наблюдение Variants.

### Открыть

`GET /api/partnerlinks/r/{token}` не требует Authorization. После проверки токена, срока и активной ссылки сервер отправляет `offer_click` и возвращает 302. Ожидание AppMetrica ограничено двумя секундами. Ошибка метрики не мешает переходу. HEAD не отправляет клик. Ответ не кешируется, Referer отключён.

Провайдер и исходный URL читаются из текущих настроек: изменение URL влияет и на ранее выданные ссылки. Смена провайдера ссылки запрещает старый редирект. Постбеки при этом продолжают проверяться по провайдеру токена. Смена Application ID делает старые токены непригодными для отправки в новое приложение; ротация Post API key того же приложения допустима.

### Принять постбек

`GET|POST /api/partnerlinks/postbacks/{provider}`. Примеры для полей `subid`, `status`, `lead_id`:

```text
GET /api/partnerlinks/postbacks/network?secret=PARTNER_SECRET&subid=TOKEN&status=approved&lead_id=123
```

```http
POST /api/partnerlinks/postbacks/network
Content-Type: application/json
X-Partner-Secret: PARTNER_SECRET

{"data":{"click":"TOKEN","status":"approved","lead":"123"}}
```

Для второго примера настройте `secretLocation=header`, `secretName=X-Partner-Secret`, поля `data.click`, `data.status`, `data.lead`. POST также поддерживает `application/x-www-form-urlencoded`; query-секрет и для POST передаётся в URL. Поля POST читаются из тела, GET — из query. Вложенные пути JSON разделяются точкой; массивы не поддерживаются. Значения атрибутов должны быть скалярами; лимит строкового атрибута — 4096 байт.

Настраиваемые поля: `token`, `status` (обязательные); `leadId`, `eventId`, `timestamp`, `amount`, `currency` (необязательные). Пустое сопоставление не передаёт параметр. `extraFields` — объект «имя параметра → путь поля партнёра». Передаются только явно сопоставленные данные; весь сырой постбек не пересылается. Сумма — конечное неотрицательное число, сохраняемое строкой без изменения точности.

`statuses` сопоставляет входящие значения с `lead`, `approved`, `hold`, `rejected`. Время — Unix seconds партнёра или время получения при отсутствии значения. Событие старше 14 дней или из будущего отклоняется. Возраст клика при этом может превышать 14 дней — ограничение относится к самому событию конверсии.

Статус не порождает дополнительный lead. Ответ 200 означает, что необходимые отправки подтверждены AppMetrica HTTP 200 сейчас или ранее; подтверждённый дубликат не отправляется снова. Ошибки доставки дают 502 без автоматического повтора. Неверный секрет даёт 403, неизвестный провайдер — 404, некорректные данные — 400, истёкший токен — 410. После явного отказа повтор выполняет партнёр; после неопределённого исхода сначала нужна внешняя сверка и ReconcileDelivery.

### Настройки для суперпользователя


`GET|PUT /api/partnerlinks/admin/config`. GET возвращает `Config` без `postApiKey`, с видимыми provider `secret` и флагами `hasPostApiKey`/`hasSecret`. Дополнительно возвращаются `locks` (общая блокировка, имена полей, событий и ID провайдеров) и каталог `presets`. GET и успешный PUT имеют `Cache-Control: no-store`. Метаданные, присланные в PUT, игнорируются; блокировки определяет сервер. PUT принимает полную конфигурацию с актуальной `version`; пропущенные/пустые секреты сохраняются. Устаревшая версия возвращает 400 с просьбой перезагрузить настройки. Настройки и провайдеры сохраняются одной транзакцией. Провайдера нельзя удалить, пока на него ссылаются записи ссылок.

Из Go используйте `Load(app)` / `Configure(app, config)`; внутри транзакции передавайте `tx`. Go Load возвращает секреты доверенному коду. Служебные записи `pl_config` закрыты для прямого Records API и realtime. Секреты, введённые в админке, сохраняются в серверной БД; её копии также содержат настройки. Значения из `Options.Managed` в `pl_config` не сохраняются.

### Как задать соответствие статусов

В **«Полях постбека» → «Статус»** укажите имя входящего поля, например `status` или `data.status`. В таблице **«Соответствие статусов»** слева вводится точное значение этого поля, справа выбирается его смысл:

| Партнёр присылает | Выберите в таблице | Событие по умолчанию |
| --- | --- | --- |
| `new` | Заявка создана (лид) | `offer_lead` |
| `1` | Подтверждение | `offer_approved` |
| `2` | Холд / ожидание | `offer_hold` |
| `3` | Отказ | `offer_rejected` |

Это пример: реальные значения возьмите из документации партнёра. В API таблица представлена как `statuses: {"new":"lead","1":"approved","2":"hold","3":"rejected"}`. Несколько значений могут соответствовать одному событию. Неизвестные значения отклоняются; статус не создаёт дополнительного лида. Названия событий в AppMetrica задаются отдельно в общих настройках.

### Секрет в теле постбека

Выберите `secretLocation: "body"`. Для JSON `secretName` поддерживает вложенный путь, например `auth.secret`:

```http
POST /api/partnerlinks/postbacks/PROVIDER_ID
Content-Type: application/json

{"auth":{"secret":"YOUR_SECRET"},"subid":"CLICK_DATA","status":"1","lead_id":"123"}
```

Для `application/x-www-form-urlencoded` используйте имя поля, например `secret`, и тело `secret=YOUR_SECRET&subid=CLICK_DATA&status=1`. GET с секретом в body не поддерживается. Сервер принимает секрет только из выбранного источника: query и заголовок не заменяют body. Секрет не включается в параметры конверсии. Примеры всех трёх способов доступны прямо в редакторе провайдера.

## События AppMetrica

По умолчанию уже заданы стандартные события плагина (пользовательские события AppMetrica): `offer_click`, `offer_lead`, `offer_approved`, `offer_hold`, `offer_rejected`. Имена меняются в настройках. Событие отправляется через Post API с `profile_id`, `application_id`, `session_type=foreground`, фактическим timestamp и `event_json`:

```json
{
  "clickData": {"clickId":"...","userId":"...","experiments":[],"issuedAt":1790000000},
  "experiments": {"offers":"premium/checkout_test/B"},
  "conversion": {"status":"approved","rawStatus":"1","leadId":"123","extra":{"offerId":"456"}}
}
```

`clickData` содержит сохранённый снимок клика, здесь она сокращена. `conversion` отсутствует у клика. Сумма остаётся параметром события. При включённом `sendRevenue` выбранный статус `revenueStatus` дополнительно отправляется в In-app Revenue, как описано ниже.

[Post API](https://appmetrica.yandex.ru/docs/ru/mobile-api/post/post-import-events) требует profileId, предварительно отправленный через SDK. По [ограничениям](https://appmetrica.yandex.ru/docs/ru/mobile-api/post/restrictions), если profileId назначен в первой и единственной сессии, загрузка по нему возможна после повторного входа. Профиль должен быть актуален (SDK-данные за последние шесть месяцев). HTTP 200 подтверждает приём загрузки, а появление события в отчётах происходит позднее.

## Ограничения выбранной схемы

- Сохраняются снимок клика и текущее состояние конверсии. Истории переходов, сырых постбеков, очереди и автоматических повторов нет. Подтверждённые события каждого статуса и Revenue дедуплицируются отдельно по конверсии. Повторный редирект может увеличить счётчик кликов; потерянный клик не восстанавливается.
- Случайный токен позволяет найти конверсию, но не подтверждает отправителя статуса: поэтому секрет постбека обязателен и передаётся отдельно.
- `profile_id` всегда равен userId сохранённой конверсии. Готовая карта экспериментов фиксируется при выдаче и включается в `event_json` событий и `payload` Revenue; без exposureTokens учитываются все подходящие конфигурации, с ними — переданный контекст показанного материала.
- Размер токена не зависит от числа экспериментов. Сам снимок клика в базе ограничен 256 KiB; ошибка сохранения не возвращает ссылку.
- Штатные HTTP-логи PocketBase скрывают токен редиректа и query постбека. Для внешнего reverse proxy отдельно исключите эти URL/параметры из логов.
- Реальные ключи/партнёры не входят в демо. Демонстрационный секрет `public-demo-postback-secret` публичен.

## Заказы пользователя

`conversations` создаётся всегда при старте сервера после миграций как системная коллекция. Variants для неё недоступны. Существующая коллекция автоматически становится системной; полиморфная связь с пользователем и записи сохраняются. Одна выдача ссылки — одна запись: повторный resolve даже для того же оффера создаёт новую конверсию.

Запись хранит владельца (полиморфная связь `user`), ссылку, clickId, полный снимок `clickData`, текущий статус (`pending`, `lead`, `approved`, `hold`, `rejected`), timestamps, сумму, валюту и явно разрешённые дополнительные параметры. Постбек обновляет запись, найденную по токену. ID заявки партнёра может быть пустым, кроме событий Revenue. Первый непустой `leadId` закрепляется за этой записью; другое значение отклоняется. Один `(provider, leadId)` нельзя присвоить другой выданной ссылке, даже того же пользователя.

Старый timestamp не откатывает состояние; при одинаковом времени lead не заменяет уже известный последующий статус. Партнёр должен присылать timestamp для надёжного порядка событий. `statusChangedAt` — серверное время последнего изменения статуса, `eventTimestamp` — время события партнёра. Удаление пользователя удаляет его конверсии.

Обычный пользователь читает только свои заказы штатным Records API; суперпользователь видит все. В админке доступен штатный просмотр без создания, редактирования, дублирования и удаления. HTTP-создание, изменение, удаление и полная очистка (`truncate`) закрыты, включая суперпользователя и batch, по имени и ID коллекции. Защита действует и без Schema Lock. Схема защищена от HTTP-изменений. Для изменений из доверенного Go-кода используйте обычный `Save`.

```dart
final orders = await pb.collection('conversations').getFullList(
  filter: 'status != "pending"', // показывать заявки, исключив только выданные ссылки
  sort: '-updated',
);
```

Заказ сохраняется до отправки аналитики: сбой AppMetrica не теряет заказ, но даёт 502. Ошибка хранения даёт 503. Это текущее состояние, а не история или очередь отправок; обновление одной записи не предотвращает повторное событие AppMetrica.

## Доходы и воронка в AppMetrica

1. У провайдера включите **«Передавать доход в Revenue»** (`sendRevenue: true`). По умолчанию выключено, чтобы случайно не принять сумму займа за доход. Выберите **«Когда начислять Revenue»**: `approved` — подтверждение (по умолчанию, в том числе для старых настроек) или `hold` — холд. Выбор применяется к нормализованному статусу из таблицы соответствий, а не к названию события AppMetrica. Настройте поля ID заявки, суммы и валюты.
2. `amount` — доход от партнёра на выбранном этапе. Для Revenue требуется неотрицательная десятичная запись, максимум 10 цифр до точки и 8 после, без экспоненты. `currency` — трёхбуквенный код, например `RUB`. Отсутствующие/неверные значения отклоняются до сохранения и отправки событий.
3. Только выбранный `revenueStatus` отправляет обычное событие и `POST /logs/v1/import/revenue`: `one_time_purchase`, price, currency, quantity=1, product_id=linkId, profile_id и foreground. Payload содержит clickData и conversion, в том числе leadId/providerId/эксперименты. Время — исходный timestamp принятого постбека; повтор сохраняет его и первоначальную сумму. Остальные статусы отправляют только обычные события. При `revenueStatus: "hold"` переход hold → approved не начисляет доход повторно.
4. Доходы смотрите в отчётах монетизации. В разделе воронок создайте шаги `offer_click → offer_lead → offer_approved` или завершите воронку на `offer_hold`, если доход учитывается на холде; для отложенных постбеков используйте воронку между сессиями и подходящий период конверсии. При переименовании событий обновите шаги. Отказы/холды смотрите отдельно в событиях. Воронка по пользователям не равна конверсии отдельных заказов при нескольких заявках одного пользователя.
5. При необходимости пометьте `offer_lead` и `offer_approved` как конверсионные события в настройках AppMetrica. Это настройка отчётов в аккаунте AppMetrica, плагин её не создаёт. Загрузка через Post API отображается с задержкой (по документации синхронизация раз в четыре часа).

Каждый статус отправляется один раз после подтверждённого HTTP 200 AppMetrica. Revenue имеет отдельную квитанцию: повтор статуса, изменение суммы или переключение revenueStatus не начисляют подтверждённый доход повторно. Если событие принято, а Revenue явно отклонён, повтор партнёра отправляет только Revenue. `transaction_id = clickId` служит стабильным идентификатором сверки, без предположения о дедупликации на стороне AppMetrica.

Скрытое поле `deliveryState` хранит квитанции `pending/unknown/sent`; оно недоступно даже через суперпользовательский Records API. Перед внешним запросом исход становится `unknown`, после подтверждения — `sent`, после явного HTTP-отказа — `pending`. Таймаут/обрыв/перезапуск до сохранения ответа оставляет `unknown`: повтор автоматически не отправляется и возвращает 502. После внешней сверки доверенный Go-код вызывает `ReconcileDelivery(app, conversationID, "event_approved" или "revenue", delivered)`. `false` разрешает следующую попытку партнёра, `true` отмечает доставку. Старые уже конвертированные записи без квитанций считаются неопределёнными, а не автоматически успешными. Очереди и exactly-once доставки нет; корректировки выплат/возвраты требуют отдельного контракта. Последующий rejected не вычитает доход.

Это интеграция обычных событий и Revenue. Нативный отчёт **«Офферы» / Product Flow** требует типизированных offer-событий. В актуальной документации их S2S-передача через POST API ещё обозначена как будущая возможность; `offer_*` не заполняют его автоматически.

Официальная документация: [Revenue](https://appmetrica.yandex.ru/docs/ru/mobile-api/post/post-revenue), [воронки](https://appmetrica.yandex.ru/docs/ru/mobile-reports/funnels-report), [конверсионные события](https://appmetrica.yandex.ru/docs/ru/mobile-tracking/conversions), [Post API и задержка](https://appmetrica.yandex.ru/docs/ru/mobile-api/post/about), [типизированные офферы и ограничение S2S](https://appmetrica.yandex.com/docs/ru/data-collection/offers).


## Атрибуция реально показанных экспериментов

Resolve принимает `{ "exposureTokens": ["..."] }` (до 30 контекстов) или прежнее пустое тело. Контексты из `variantContext` проверяются сервером; подделка, чужой/просроченный token или конфликт назначений дают 400 до создания конверсии. Контекст не обходит ViewRule. С ним `attributionBasis = content_exposure`, без него — `current_assignment`; последнее не доказывает показ. Выдача сохраняет снимок в одной транзакции с выбором текущей политики открытия.

Для `dynamic_link_settings` проверяются актуальность набора, версии и ревизии: если политика изменилась, resolve возвращает 409; обновите и перерисуйте экран, не подменяйте контекст уже записанного нажатия. Старый контекст дизайна/порядка можно использовать для всё ещё показанного материала. В серверных событиях общие верхние ключи: `experiments`, `attributionBasis`, `exposures`, `clickId`, `linkId`; подписанные tokens не сохраняются. Клики и постбеки используют один profile_id и снимок экспериментов.

Подробный клиентский контракт и настройка отчёта: [воронки экспериментов](../../docs/EXPERIMENT_FUNNELS.md).
