# Push

- `Register` до Bootstrap/Start. `Options.MCP` опционален, реализация через `MCPTools()`; MCP не должен импортировать Push. UI и MCP вызывают одни доменные операции.
- Коллекции `push_*` системные. Только приватный save-контекст; конфигурация, токены, снимки заданий не доступны через Records/realtime. OAuth token не показывается, не логируется. Application ID нельзя менять при существующих привязках.
- `Options.Managed` закрепляет поля; `LockAdminConfig` запрещает HTTP-запись даже суперпользователю. Токен из Managed не сохраняйте в базе и не выдавайте API. При старте фиксируйте Application ID и проверяйте существующие привязки, чтобы смена кода не обходила защиту.
- Устройства принадлежат auth-пользователю из запроса, смена установки требует её секрета. Не принимайте userId/profileId от клиента. Поколение привязки проверяется перед отправкой и при открытии.
- Аудитории: типизированные И/ИЛИ/НЕ, SQL только из проверенной схемы; conversion same-row; назначения Variants через его публичный UserSelection. Не добавляйте произвольный SQL.
- Рассылка всем требует явного `Campaign.AllUsers`; пустой AudienceIDs сам по себе не расширяет охват. Учитывайте только подключённые auth-коллекции и существующих владельцев; исключения и лимиты продолжают действовать.
- Запуск идемпотентен по requestKey, хранит снимок кампании/аудиторий. У немедленного снимок устройств создаётся атомарно; у scheduled — при наступлении расписания. HTTP launch не делает сетевых отправок.
- Не держите DB-транзакцию во время HTTP. Задание фиксирует unknown и client_transfer_id до обращения к AppMetrica. Не повторяйте неопределённые отправки автоматически. sent не равно delivered.
- Атрибуция: последнее проверенное открытие за 7 дней до выдачи партнёрской ссылки, фиксируется в clickData.push через callback Partner Links. Тестовые запуски не атрибутируются. Не меняйте источник при позднем постбеке.
- Проверки: Go race, версия/откат, idempotency, отказ без изменений, concurrent launch, провайдер-заглушка, смена владельца, MCP scopes, Flutter ID/secret retry и UI в двух темах.

- Метрики analytics/analytics_overview получают значения из AppMetrica Reporting API, не из локальных конверсий. Сохраняйте разделение ошибок/нулей и кэш. Удаление черновиков не удаляет снимки/историю запусков; незавершённая кампания и используемая аудитория защищены.
