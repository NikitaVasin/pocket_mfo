# Schema Lock: инструкция для агента

Используйте, когда схема управляется кодом, а администраторы редактируют содержимое и Variants. Защита распространяется на HTTP, включая SDK и суперпользователей. Доверенный Go-код и миграции остаются доступны. Документация и матрица доступа — [README.md](README.md).

## Как подключать

Вызовите `schemalock.Register(app)` до Bootstrap / Start, обычно после остальных плагинов. Новых таблиц и миграций нет. Плагин включён в example постоянно. Его регистрация активирует `variants.LockAdminRules`; сама по себе она не подключает Variants.

## Инварианты и сопровождение

- HTTP middleware использует явный список сочетаний метода и шаблона маршрута. Неизвестные `/api`-маршруты запрещены. Не заменяйте список запретом только известных опасных путей.
- Разрешены CRUD, auth, файлы, realtime, штатный batch, чтение схемы/метаданных и рабочие API плагинов. CRUD `_superusers` разрешён; остальные системные записи через HTTP только читаются. Служебные ограничения других плагинов сохраняются.
- Настройки сервера, cron list/run, логи, экспорт схемы, создание/загрузка/скачивание/удаление бэкапов разрешены. SQL, импорт, restore, truncate, изменение коллекций/полей/индексов/API rules/auth-схемы и переключение Singleton запрещены.
- Cron выполняет уже зарегистрированный доверенный Go-код. Не добавляйте разрешённый endpoint с произвольным SQL, выполнением кода или общей записью схемы.
- Variants может управлять своей служебной схемой. Подмена исходных ListRule/ViewRule через HTTP должна отклоняться внутри транзакции публикации; изменение через Go Publish допустимо.
- Запрет записи системных записей должен работать по ID и имени коллекции, напрямую и внутри batch. Batch может вернуть внешний 400 с вложенным отказом; вся транзакция должна откатиться.
- UI загружается после остальных расширений, скрывает опасные действия и заменяет редактор коллекции окном Variants. Защита действует и без UI. Сохраняйте просмотр системных записей, настройки, темы, Singleton и relation picker.
- Не добавляйте HTTP/DB/UI-переключатель отключения. Новые разрешения вносите только в Go и сопровождайте тестами.
- Восстановление бэкапа — операторская процедура из доверенного кода или при остановленном сервере. Не добавляйте обходной HTTP-маршрут. Не запускайте restore во время обычного тестирования пользовательских данных.

Проверки: `go test -race ./plugins/schemalock ./plugins/variants` и `npx playwright test --project=schemalock`. Для каждого нового разрешения проверьте соседние запрещённые методы, а для отказов — отсутствие изменений схемы/настроек/данных. Тесты редакторов без защиты должны оставаться в проекте `plugins` на отдельном стенде.

- Настройки AppMetrica и провайдеров Partner Links через HTTP только читаются; PUT config запрещён, UI получает locks.all. Изменение ссылок сохраняется.
