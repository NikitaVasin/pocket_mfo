# Schema Lock

Защита схемы для PocketBase **v0.40.4**. Суперпользователи работают с записями, Variants и настройками сервера, а схема меняется из Go и миграций. Ограничения действуют на HTTP API, включая прямые запросы SDK; скрытие кнопок — только оформление интерфейса.

```go
polymorphicrelation.Register(app)
variants.Register(app)
singleton.Register(app)
schemalock.Register(app) // до Bootstrap / Start
```

Регистрация идемпотентна, порядок относительно существующих плагинов не влияет на защиту. UI Schema Lock загружается последним. Дополнительных таблиц и миграций нет. В `example` плагин включён всегда.

## Доступные действия

| Действие | Доступ |
| --- | --- |
| CRUD обычных записей, включая файлы и batch | По штатным правам PocketBase |
| CRUD `_superusers` | Разрешён суперпользователям; новые администраторы также ограничены Schema Lock |
| Прямой CRUD остальных системных коллекций | Только чтение; создание, изменение и удаление запрещены, включая batch |
| Подключение Variants, варианты, условия, эксперименты, группы, предпросмотр | Через кнопку **Variants** обычной коллекции |
| Базовые List/View API rules Variants | Только из Go; HTTP-подмена отклоняется внутри транзакции публикации |
| Схема: коллекции, поля, индексы, API rules, auth-настройки, view | Только из кода |
| SQL, проверка SQL view, импорт схемы, truncate, переключение Singleton | Запрещены через HTTP |
| Настройки сервера, почта, файловое хранилище | Доступны по штатным правам суперпользователя |
| Cron и логи | Просмотр и запуск зарегистрированных cron, просмотр и очистка логов разрешены |
| Экспорт схемы | Разрешён |
| Бэкапы | Создание, загрузка, скачивание и удаление разрешены; восстановление запрещено, поскольку заменяет схему |

В интерфейсе системные записи открываются в штатном окне просмотра; Variants редактируется из целевой коллекции, а не через `pv_configs`/`pv_sets`. Singleton, уже настроенный из кода, продолжает работать.

Чтение схемы, метаданных и конфигурации Singleton сохранено для работы штатной админки. Авторизация, realtime, файлы и healthcheck работают. Настройки, экспорт и логи доступны в навигации. Скрыты только SQL-консоль, импорт схемы и восстановление бэкапа; прямые ссылки на SQL и импорт перенаправляются к настройкам приложения.

## Границы защиты

Middleware разрешает только перечисленные в `plugin.go` шаблоны маршрутов и HTTP-методы. Остальные `/api`-операции возвращают `403`; при расширении приложения новые маршруты нужно явно разрешить в серверном коде. CORS preflight не является операцией приложения и пропускается. Ошибки запрещённых операций внутри batch PocketBase возвращает как `400` с откатом всей транзакции.

Плагин не ограничивает доверенный Go-код, CLI и миграции. `app.Save`, `variants.Publish` и `singleton.Configure` доступны программно. Запуск cron выполняет зарегистрированный серверный код; новые задания по-прежнему регистрируются только из кода. Variants может менять только собственную служебную схему через свой API; базовые правила при подключении берутся из коллекции и далее сохраняются до изменения из кода. Переключателя отключения защиты через UI, HTTP или БД нет.

Обновление PocketBase требует проверки списка маршрутов и UI API. Тесты проверяют запреты, отсутствие побочных изменений, системные записи, batch, Variants, файлы, realtime и интерфейс.

## Восстановление резервной копии

Schema Lock оставляет восстановление оператору сервера. Оно заменяет и данные, и схему, поэтому кнопка Restore и HTTP-маршрут закрыты. Создать, загрузить и скачать архив в админке можно.

Для доверенного серверного кода PocketBase предоставляет `app.RestoreBackup(ctx, "backup.zip")`: после Bootstrap он берёт архив из настроенного хранилища бэкапов, восстанавливает данные и перезапускает процесс. Это операция обслуживания, а не код для выполнения при каждом запуске. В v0.40.4 она экспериментальная, поддерживается на UNIX и требует свободного места примерно вдвое больше восстанавливаемого архива данных.

Альтернатива — остановить сервер, сохранить текущий каталог данных отдельно, восстановить содержимое проверенного архива в каталог данных с правильными правами и запустить совместимую версию приложения. Для Docker используйте именно volume `/pb_data`, а не каталог исходников. Сначала проверьте процедуру на отдельной копии: при запуске приложение может применить свои миграции к восстановленной схеме. Не копируйте файлы SQLite поверх работающей БД.

Защита Schema Lock после перезапуска сохраняется, поскольку подключена в бинарнике. Экспорт одной схемы не заменяет полный бэкап: конфигурации Variants и Singleton находятся в служебных записях.
