# Singleton: инструкция для агента

Используйте для главной страницы, настроек контента и других сущностей с максимум одной записью. С Variants ограничение действует отдельно для каждого набора. Пустые коллекции/наборы допустимы; автосоздания и наследования Default нет. Документация — [README.md](README.md).

## Как подключать

Вызовите `singleton.Register(app)` до Bootstrap / Start, затем настройте уже существующую обычную коллекцию:

```go
_, err := singleton.Configure(app, singleton.Config{
    Collection: "homepage", Enabled: true,
})
return err
```

`Load(app, "homepage")` возвращает конфигурацию; для существующей, но ещё не настроенной коллекции — `Enabled: false`. `Configure` возвращает нормализованный ID. Конфликт нескольких записей — `*ConflictError` с наборами и количеством записей; выбор удаляемых данных остаётся за пользователем.

Без Schema Lock есть вкладка Singleton в редакторе коллекции. С Schema Lock настраивайте режим из Go/миграции; форма содержимого остаётся доступна. CRUD, файлы, realtime и права доступа — штатные PocketBase.

## Инварианты и сопровождение

- Поддерживаются только несистемные Base-коллекции, не auth/view.
- Гарантию даёт уникальный SQLite-индекс `idx_ps_*` по `(1)` или по `content_set`. Не заменяйте его предварительным подсчётом: это сломает конкурентные записи.
- Ограничение распространяется на суперпользователей, Save и SaveNoValidate. Перенос записи в занятый набор должен отклоняться. Включение при конфликте не должно менять схему/данные или удалять лишние записи.
- Настройки — служебная `ps_configs`. Не изменяйте её напрямую. Экспорт схемы не переносит эти записи; полная резервная копия переносит.
- При подключении Variants пересоздавайте индекс в той же транзакции. Оба порядка регистрации должны работать. Выключение Singleton сохраняет содержимое и конфигурацию Variants.
- UI заменяет список формой только на основной странице коллекции, не внутри relation picker. Сохраняйте предупреждение о несохранённых изменениях и выбранный набор в URL.
- Основная логика — `plugin.go`; интерфейс — `ui/main.js`.

Проверки: `go test -race ./plugins/singleton ./plugins/schemalock` и `npx playwright test singleton.spec.js schemalock.spec.js`. Особенно важны конкурентное создание, оба порядка регистрации, конфликты наборов, rollback, API rules и realtime.
