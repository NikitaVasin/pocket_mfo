# Singleton

Плагин для PocketBase **v0.40.4**: максимум одна запись в обычной коллекции, а с Variants — максимум одна запись на каждый `content_set`, включая группы экспериментов и архивы. Пустые наборы разрешены. Данные не создаются автоматически и не наследуются из `default`.

## Подключение

```go
import "github.com/NikitaVasin/pocket_mfo/plugins/singleton"

singleton.Register(app) // до Bootstrap / Start
```

Работает самостоятельно и вместе с `variants.Register(app)` в любом порядке. В example оба плагина уже подключены. UI встроен в Go-бинарник.

## Включение через интерфейс

Доступно в приложении без Schema Lock. В защищённом example режим задаётся через `singleton.Configure` в миграции; работа с содержимым формы остаётся доступна.

1. Создайте обычную **Base**-коллекцию и сохраните поля.
2. Откройте **Collection settings → Singleton**.
3. Включите **Одна запись на коллекцию** и нажмите **Применить**.

Если одновременно редактировали схему, сначала сохраните её через **Save and continue (Ctrl+S)**. Переключатель Singleton применяется отдельно. Auth-, view- и системные коллекции не поддерживаются.

Если уже несколько записей, включение отклоняется. С Variants показываются названия и количество записей в конфликтующих наборах. Выберите, какие записи оставить, самостоятельно; плагин ничего не удаляет.

После включения коллекция открывает форму на странице вместо таблицы. Пустой набор показывает создание, существующая запись — редактирование. Доступны **Сохранить**, **Сбросить**, **Удалить**. Перед уходом с несохранёнными изменениями появляется подтверждение. При ошибке сохранения введённые значения остаются в форме.

Переключатели вариантов, групп экспериментов и архивов находятся над формой. Выбор сохраняется в URL; без выбранного набора открывается `default`. Поиск, пагинация и создание дополнительной записи скрыты. Штатные relation-picker остаются списками выбора.

Выключение Singleton возвращает таблицу и возможность создавать несколько записей. Существующие данные и настройки Variants сохраняются. Настраивать Variants можно как до включения Singleton, так и после: имеющаяся единственная запись становится `default`.

## API и гарантии

CRUD и realtime используют штатные API PocketBase и прежние API rules. Singleton не предоставляет дополнительных прав. С Variants по-прежнему действуют персонализированное чтение и изменение контента только суперпользователями.

```dart
final records = await pb.collection('homepage').getList(page: 1, perPage: 1);
final homepage = records.items.firstOrNull;
// null: доступной записи нет; автоматического fallback нет.
```

Go-настройка возвращает нормализованный ID коллекции:

```go
cfg, err := singleton.Configure(app, singleton.Config{
    Collection: "homepage", Enabled: true,
})
cfg, err = singleton.Load(app, "homepage")
```

`Load` возвращает `Enabled: false`, если режим ещё не настраивался. Ошибка `*singleton.ConflictError` содержит `Conflicts` с `Set`, `Name`, `Count`.

Только суперпользователям доступны:

- `GET /api/singleton/admin/collections/{collection}` → `{collection, enabled}`.
- `PUT /api/singleton/admin/collections/{collection}` с `{ "enabled": true }` или `false` → применённая настройка.
- При конфликте PUT возвращает HTTP 400 с `data.conflicts`: массивом `{set, name, count}`. Схема и данные остаются прежними.

Ограничение обеспечивается уникальным SQLite-индексом: по константному выражению `(1)` или по `content_set`. Одновременные запросы не создадут вторую запись. Ограничение действует для суперпользователей, `app.Save` и `app.SaveNoValidate`. Перемещение записи в занятый набор также отклоняется. Управляемый индекс нельзя убрать или изменить через схему — используйте вкладку Singleton.

Настройки хранятся в системной коллекции `ps_configs`; прямое редактирование её записей и схемы запрещено. Переименование целевой коллекции сохраняет настройку, удаление коллекции убирает её конфигурацию. Полная резервная копия PocketBase сохраняет режим; экспорт одной схемы без системных записей не переносит конфигурацию. Прямое изменение SQL-схемы в обход плагина не поддерживается.

## Пример

В общем стенде **demo_homepage** содержит по одной записи в шести наборах, настроенных аналогично `demo_offers`. Выбор коллекции сразу открывает редактирование главной страницы; переключатели позволяют просматривать разные аудитории и группы эксперимента. Повторный запуск миграции не перезаписывает пользовательские изменения.
