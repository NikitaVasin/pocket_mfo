# Variants

При подключённом [Schema Lock](../schemalock) редактор открывается кнопкой **Variants** на странице коллекции. Подключение плагина, варианты и эксперименты доступны; базовые List/View rules меняются только через Go (`Publish`). Прямое изменение системных записей Variants запрещено. Описанное ниже редактирование API rules через админку относится к режиму без Schema Lock.

Персонализированные наборы записей и эксперименты для PocketBase **v0.40.4**. Подключение до `Bootstrap`/`Start`:

```go
variants.Register(app)
```

В общем `example` плагин уже зарегистрирован. Отдельная сборка UI не нужна.

## Настройка в админке

1. Создайте обычную коллекцию контента и задайте её исходные `ListRule`/`ViewRule`.
2. Откройте **Collection settings → Variants**, выберите auth-коллекцию.
3. Включите **Variables**, добавьте варианты и условия. Кнопки «Выше»/«Ниже» задают приоритет: первое совпадение выигрывает.
4. При необходимости включите **Experiments**, добавьте эксперимент внутри варианта и группы. Диапазоны `1…10000` не должны пересекаться. Можно распределить поровну или задать долю первой группы в процентах.
5. Нажмите **Опубликовать варианты**. Настройки применяются сразу, отдельно от сохранения обычной схемы коллекции. Если в том же окне изменены имя, поля или индексы коллекции, сначала сохраните их через **Save and continue (Ctrl+S)**, затем публикуйте Variants. Черновик вариантов при этом сохраняется.
6. Выберите вариант и, при необходимости, группу эксперимента над таблицей, затем нажмите **New record**. Новая запись автоматически попадёт в выбранный набор; поле набора в форме скрыто. Кнопка **Открыть записи набора** во вкладке Variants открывает обычную таблицу с нужным пресетом.

Вкладка Variants сначала показывает компактный список вариантов с кратким описанием условий. Откройте вариант, затем нужную группу условий или эксперимент. Условия редактируются строками «поле → оператор → значение»; на узком экране поле переносится над оператором и значением. Новые варианты и эксперименты раскрываются автоматически, сворачивание не теряет несохранённые изменения. Значок колбы помечает варианты с экспериментами и в настройках, и в селекторе над таблицей.

Над таблицей персонализированной коллекции находится селектор **Вариант**: базовый вариант всегда называется `default`. Выбор варианта открывает его базовый набор. Если у него есть эксперимент, рядом появляется **Вариант эксперимента** с группами и базовым набором `default`. Когда есть только базовый вариант, первый селектор скрыт; без эксперимента скрыты оба. Архивные варианты и группы помечены отдельно; при нескольких экспериментах названия групп включают название эксперимента.

Пресеты создаются автоматически. При открытии коллекции без выбранного набора применяется `default`; общего просмотра всех вариантов в интерфейсе нет. Поиск уточняет записи внутри выбранного набора. Выбор и фильтр сохраняются в URL; работают штатные сортировка, подгрузка и счётчик записей. Служебное поле `content_set` скрыто в таблице и форме записи, но остаётся в API. При редактировании запись сохраняет свой набор, даже если открыта поверх другого пресета. Новые записи без контекста пресета (например, во вложенной форме другой коллекции) получают `default`.

Вкладка **API rules** таких коллекций показывает только ваши `List/Search rule` и `View rule`. Нажмите **Опубликовать правила**, чтобы применить изменения. Плагин объединяет их с выбором набора через `AND`; служебные выражения скрыты из редактора. Например, `@request.auth.id != ""` в обоих полях запрещает гостям читать записи и сохраняет выбор вариантов для авторизованных пользователей. Те же исходные правила доступны во вкладке **Variants**; создание, изменение и удаление контента остаются доступны только суперпользователям.

Существующие записи становятся `Default / base`. Все записи принадлежат ровно одному набору. Наборы не наследуются: выбранный пустой набор возвращает пустую выдачу. Штатный Duplicate создаёт новую запись в текущем пресете. При восстановлении черновика новой записи её набор также определяется текущим пресетом.

При первой публикации сохраняются исходные API rules; после неё они редактируются во вкладке Variants. Чтение остаётся ограничено этими правилами, в том числе `null` (только суперпользователи). Создание, изменение и удаление персонализированного контента доступны только суперпользователям. Ключи вариантов/экспериментов/групп стабильны: переименование отображаемого названия не меняет набор; новый ключ означает новый набор.

Удаление варианта/эксперимента из конфигурации не удаляет его записи и историю. Старые наборы помечаются архивными и остаются видны администратору. Выключение Experiments возвращает базовый набор варианта; выключение Variables — только Default. Наборы не раскрываются всем пользователям.

## Правила аудитории

Конструктор поддерживает:

- `all` / `any`: И / ИЛИ;
- `field`: сравнение поля через `eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `contains`, `notContains`, `empty`, `notEmpty`;
- `exists` / `notExists`: наличие / отсутствие связанной записи, удовлетворяющей вложенному условию.

Доступны текст, email, URL, числа, boolean, даты и одиночный select. Скрытые поля, пароли, JSON и многозначный select не используются в условиях. Для relation применяется отдельная область `exists`: все её вложенные условия относятся к **одной связанной записи**. Поддерживаются прямые и обратные связи (`subscriptions_via_user`), включая множественные relation. Условия могут быть вложены до 6 уровней, максимум 200 узлов на конфигурацию.

Персонализированные, системные служебные коллекции плагина и view-коллекции не могут быть зависимостями аудитории. Нельзя удалить/переименовать используемое поле так, чтобы сломать опубликованное условие: сначала измените конфигурацию. Изменения данных учитываются без публикации и фонового пересчёта.

Гости получают Default при разрешающих исходных API rules. Авторизованное чтение доступно пользователям выбранной auth-коллекции; пользователи других auth-коллекций не получают записи или назначения этой коллекции. На коллекцию выбирается одна auth-коллекция; после первой публикации её нельзя заменить.

## Бакеты и эксперименты

В выбранную auth-коллекцию добавляется скрытое поле `content_bucket`: `1…10000`, `0` — ещё не назначено. Бакет вычисляется из SHA-256 от `authCollectionId + "\x00" + userId`, первые 8 байт big-endian, `% 10000 + 1`.

Бакет назначается новым пользователям при сохранении, существующим — при первом авторизованном HTTP-обращении или сохранении записи. Он не меняется после назначения. Обычный Records API игнорирует запись скрытого поля не-суперпользователем; попытка суперпользователя изменить его отклоняется, программные сохранения сохраняют прежнее значение. Бакет не является механизмом авторизации.

Внутри варианта активен максимум один эксперимент, в нём от 2 до 30 групп. Непокрытые бакеты получают базовый набор варианта. Проценты — вероятностное распределение, не квоты. Карты всех экспериментов используют общий бакет: одинаковые карты дают совпадающие группы. Изменение границ может переводить существующих участников между группами.

## Штатные API и realtime

```dart
final offers = await pb.collection('offers').getList(page: 1, perPage: 20);
final offer = await pb.collection('offers').getOne(recordId);
final unsubscribe = await pb.collection('offers').subscribe('*', (event) {
  // PocketBase уже проверил ListRule/ViewRule для текущего пользователя.
});
```

Плагин не фильтрует готовые страницы и не заменяет CRUD/realtime PocketBase. У коллекции появляется индексированный relation `content_set`; его служебный индекс защищён от удаления и изменения назначения. Пользовательские индексы можно добавлять независимо. Для неё создаётся виртуальная view `pv_choice_<hash>`, вычисляющая набор через `CASE` и коррелированные `EXISTS`. Она **не хранит строки распределения**. Генерируемые правила используют обратную связь от текущего пользователя к view, поэтому выбор начинается с его ID, а не со сканирования всех пользователей.

Штатный PocketBase применяет правила к спискам до пагинации, отдельным записям, `expand`, защищённым файлам и realtime. Публичные файлы сохраняют стандартную публичность PocketBase; для ограниченного доступа используйте protected file. Правила не ограничивают прямой SQL и серверные `FindRecords...` — как и обычные API rules.

Realtime доставляет последующие разрешённые события. Смена аудитории/конфигурации не отправляет новый список и не очищает локальное состояние приложения; при необходимости повторите `getList`. Нет гарантий дополнительной атомарности между проверкой прав и доставкой: сохраняется штатная модель PocketBase.

## API участия

```dart
final current = await pb.send('/api/variants/me', query: {'collection': 'offers'});
final history = await pb.send('/api/variants/me/history', query: {
  'collection': 'offers',
  'page': 1,
  'perPage': 30,
});
```

`GET /api/variants/me` требует авторизации. Возвращает `{"items": [...]}`; без `collection` вычисляет решения для всех коллекций, использующих auth-коллекцию текущего пользователя. Элемент:

```json
{
  "collection": "COLLECTION_ID",
  "variant": "premium",
  "experiment": "offer_test",
  "group": "b",
  "set": "CONTENT_SET_ID",
  "version": 2,
  "bucket": 7314,
  "reason": "experiment_bucket"
}
```

У базового набора поля `experiment` и `group` отсутствуют. Причины: `default`, `variables_disabled`, `first_matching_audience`, `experiment_bucket`.

`GET /api/variants/me/history` возвращает `page`, `perPage`, `totalItems`, `totalPages`, `items`. `perPage` ограничен 100. В записи истории есть `created` и `decision`. История изолирована по паре auth-коллекция + пользователь.

Администратору доступны:

- `GET /api/variants/admin/users/{authCollection}/{userId}` — предпросмотр актуальных решений;
- `GET /api/variants/admin/users/{authCollection}/{userId}/history` — история с теми же параметрами;
- `GET /api/variants/admin/collections/{collection}` — `{config, sets}`; до настройки `config: null`;
- `PUT /api/variants/admin/collections/{collection}` — атомарная публикация конфигурации. Передайте текущую `version`, при создании — `0`. Устаревшая версия отклоняется.

Предпросмотр не меняет пользователя и не пишет историю, включая пользователя с ещё не назначенным бакетом: вычисляется его будущий стабильный бакет.

История фиксирует **наблюдавшиеся решения** при чтении HTTP, включая `expand`, вызове `/me` и успешной отправке realtime-события. Повторение того же решения не создаёт запись; параллельные изменения сериализуются транзакцией. Версия конфигурации входит в решение. Это не журнал фактических показов и не точная временная шкала изменений у отсутствующего пользователя. Удаление пользователя удаляет его историю и последнее наблюдение.

## Программная настройка

```go
cfg, err := variants.Publish(app, variants.Config{
    Collection: "offers", AuthCollection: "users",
    Variables: true, Experiments: true,
    Default: variants.Variant{Key: "default", Name: "Default"},
    Variants: []variants.Variant{{
        Key: "premium", Name: "Premium",
        Condition: &variants.Condition{
            Kind: "field", Field: "premium", Op: "eq", Value: true,
        },
        Experiments: []variants.Experiment{{
            Key: "offer_test", Name: "Новая подборка", Active: true,
            Groups: []variants.Group{
                {Key: "a", Name: "A", From: 1, To: 5000},
                {Key: "b", Name: "B", From: 5001, To: 10000},
            },
        }},
    }},
})
// Обработайте err. При изменениях загрузите cfg через variants.Load,
// измените его и снова вызовите Publish, сохранив текущую Version.
```

Служебные коллекции `pv_configs`, `pv_sets`, `pv_states`, `pv_history` и `pv_choice_*` находятся в системном разделе админки. Схема и записи управляются плагином; их прямое редактирование запрещено. Полная резервная копия PocketBase сохраняет всё состояние. Экспорт одной схемы без служебных записей не является переносом конфигурации плагина.

Публикация не перебирает пользователей. Только первое включение размечает существующие строки самой коллекции контента. Сложность последующих запросов зависит от условий и индексов связанных таблиц; для обратных связей и часто используемых условий добавляйте соответствующие индексы. Метрики показов, конверсии и статистика A/B-тестов в этот модуль не входят.

### Карта для аналитики

`GET /api/variants/me` сохраняет `items` и дополнительно возвращает `experiments`, например `{"offers":"premium/checkout_test/B","dynamic_link_settings":"default"}`. Ключ — имя коллекции; значение — стабильные ключи варианта/эксперимента/группы, либо только варианта, если активного эксперимента нет. Отключённые Variants исключаются. Общая функция Go `AnalyticsExperiments(app, decisions)` используется также Partner Links для сохранённого снимка конверсии.
